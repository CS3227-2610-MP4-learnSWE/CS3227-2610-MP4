# learnSWE Preview User Guide

Start the app using [README.md](../README.md). This guide covers the current preview; the feature list and user stories describe future production behaviour.

## Enter a workspace

At `/login`, use **Sign in** with your email and password. The server decides your role (student, teacher or admin) and takes you to that workspace; opening another role's page sends you back to your own. To register, choose **Create account**, enter a display name, email and a password of 10 to 128 characters (not a common password and not your email), then sign in. Accounts created this way are always student accounts; the page gives the same reply whether or not the email was already registered. **Log out** in the sidebar ends the session. You stay signed in for up to 12 hours. After too many failed attempts the page says how long to wait.

Separately, the **Demo shortcut (development)** buttons under the form open sample-data screens with no account and no session. In that demo mode the sidebar says "Demo (not signed in)", and you can switch roles using the header selector or return to the login page using the footer link. Demo mode cannot use live practice or the study companion: those show "Sign in to use live practice and the study companion". A signed-in user does not see the role selector.

The sun/moon button toggles light/dark mode. The initial theme follows your operating-system preference. Theme and other local state reset on refresh. On narrow screens, open the navigation drawer with the menu button.

## Student

- Overview shows illustrative progress, activity and course suggestions.
- Study materials supports topic filters and title search. Open a lesson, mark it complete, then mark it incomplete if desired. Completion updates the overview until refresh.
- Practice (requires a student sign-in) loads one set of single-answer MCQs from the server (code snippets can appear in a question, but answers are selected choices, never free text). Answer every question and submit the whole set in one action; if any is unanswered, nothing is sent and the page names the missing question numbers. After a successful submission the score, your choice, the correct answer and the explanation for each question come from the server, and the choices lock. "Start another attempt" gives an empty form. If the server cannot be reached or fails, the page says so, keeps your answers and offers "Try again". If the failure happens after your answers were saved on the server, they are locked and "Try again" finishes the submission. Answers and results are kept while you move between student pages; a browser reload starts fresh. The student identity is a fixed placeholder until real login exists. The hint panel is a scripted demo, not AI. After submission a wrong answer is marked in red (your choice outlined in red, its explanation on a red background) and the correct choice is outlined in green; a right answer stays green, and the score banner turns amber unless every answer is right.
- The study companion is a bottom-right chat icon on every student page. Click it to open the chat box; Close or Escape minimises it and preserves messages and the unsent draft. The refresh icon clears both and starts fresh without reloading the page. Messages survive navigation within the student workspace; browser reload, returning to login or switching demo roles clears this temporary chat. Type a question (up to 1,000 characters; a counter under the box shows how many you have used, and a note appears if text beyond the limit was not added) and send it; a "Thinking..." note shows while the reply is on its way, and replies appear as plain text. If something goes wrong (no connection, the service is busy or unavailable, too many messages) the widget says so in plain words, keeps what you typed and lets you send again. You can send up to 20 messages a minute and 300 a day; past that it says how long to wait. In this preview everyone shares the placeholder student id, so that limit is shared by everyone using the same deployment. Replies come from the SoC language model and can be wrong. The server decides what the companion may do: on the Practice page before you submit, it gives a short hint and a guiding question and does not state or confirm answers (it is not given the answer choices or the answer key); after you submit, open the companion from the Practice page results and it can explain that attempt, but if you have started a newer unsubmitted attempt it goes back to hints; on other pages it gives short app help and general software engineering explanations, says this is not course material and declines off-topic requests. If you paste a practice question into the chat on any page, you get a hint, not the answer. A check on the server blocks replies that name the right choice by letter in common forms (for example "the answer is b", "b is the answer", "Option A", "Correct: b", "the correct one is b", "answer = b", a tick, or a list such as "q1: a, q2: b"), that quote its text, or that mark a choice right or wrong; a blocked reply is replaced by a fixed message saying answers cannot be shared. This check is not perfect: a hint can still point towards an answer in other words, and other phrasings can still get through, such as paraphrases, "go with b", "pick B", "choose b", "the best choice here is b", hedged wording such as "the answer is probably b" or "the answer here is b", "the second option", letters written with look-alike Cyrillic characters, letters inside HTML tags, "[b]", spaced-out letters or numbers written as words. The companion does not use lesson content yet, so it cannot cite lessons. It needs the backend to be set up with the SoC LLM settings; otherwise it says it is unavailable. In the future authenticated app, chat should remain account-scoped until logout/explicit clear, including across reload.
- Inbox starts with two unread messages. Opening one marks it read and updates the count. Open the survey link to see a sample feedback form. Its submission button shows a preview message without saving anything.

## Teacher

- Materials library uses real PostgreSQL records and private source files. Select a managed course, optionally filter by topic or search, upload a PDF or UTF-8 text file (up to 10 MiB), download the original, or change its topic. Cancelling upload clears the form and errors. Uploading does not publish a lesson.
- AI content studio generates concise study-note drafts from one source. Choose a course and source, then **Generate draft notes**. Generation sends source text to the SoC LLM; it needs the backend SOCLAAS settings. Inputs must have at most 8,000 normalised characters and 100 PDF pages. Scanned PDFs need a text-based source; longer sources are rejected rather than shortened.
- Successful drafts are saved in PostgreSQL and listed under **Saved drafts**. Open a draft to see its source title, creator and creation time. The URL can reopen the draft after refresh/restart. Every success creates a new unpublished draft; no student can read it through the teacher API. Notes may be inaccurate and require teacher review. Approval and publication remain unimplemented.
- In **Practice questions**, choose a course/source and **Generate 3 draft MCQs**. Every successful request saves a new batch of three questions, each with four choices, one correct answer and an explanation. Open **Saved MCQ batches** to review a read-only batch; its URL reopens it after refresh or backend restart. Answers are visible only in the teacher workspace. All batches show **Unpublished draft · Review required**: AI may be inaccurate, and editing, practice-set assembly and publication are not available yet. Source limits and the real-request notice match note generation; malformed or truncated AI output is rejected without saving a partial batch. Generation disables selection/duplicate clicks. Explicit retry can create another batch if the first response was lost; no automatic retry occurs.
- Open a saved draft and choose **Edit notes**. Change its title or content, then **Save changes**; no AI call is made. Titles allow 1–200 characters and note content 1–2,000 Unicode characters after trimming/line-ending normalisation. The counter and validation explain the limit. The source title and original creator stay unchanged; last editor/time update on save.
- **Cancel** discards local edits after confirmation when needed. Navigation to another draft/course/page, including browser back/forward, asks **Keep editing** or **Discard changes** when edits are unsaved. A pending save must finish before in-app departure. Refresh/tab close uses the browser's native warning where supported; discarded/reloaded local edits are not stored.
- Failed saves keep your input and offer **Retry save**. Another teacher's save gives a conflict: **Load latest saved version**, then confirm discarding local edits, before editing the newer version. Failed latest loads preserve your local input. There is no force-overwrite; after a lost save response an explicit retry may report a conflict because the first save already committed.
- Unusable generated notes are rejected without saving a draft. Generation failures keep the selected source and existing drafts. Try generation again explicitly; if the previous response was lost, another saved draft may be created. Rate-limit failures say how long to wait when available. If you navigate away from a pending generation or change its selection, a late response cannot reopen it or display an obsolete error, even after returning to the same page.
- The teacher workspace still uses an explicitly labelled development identity, not the sign-in above: these screens work from the demo shortcut when the local development switches are on, and signing in as a teacher does not yet grant them access. Other teacher screens remain sample previews.

## Admin

- Analytics has sample reporting periods and labelled illustrative figures.
- Feedback forms lets you edit questions, required flags, audience and related feature. Preview survey request opens a summary without creating a form or sending a request.
- Feedback insights offers sentiment filtering, fixed AI analysis and links to supporting sample responses.
- Announcements accepts a subject/message and shows a recipient preview. Nothing is sent.
- People & access filters fictitious records by role. Preview access cannot change permissions.
- AI usage displays illustrative requests/failures; actual token usage is explicitly unavailable.

## Limitations and recovery

The demo shortcut screens are public local demonstrations with unrestricted role switching. Do not use real credentials or sensitive materials in them. Preview state is temporary; refresh returns to sample defaults. Teacher material metadata and files persist in PostgreSQL and private storage. Unknown routes return to login or a role-specific not-found view. An unavailable backend shows a footer status and does not prevent exploring screens, except the student Practice page, which needs the backend to load questions. The practice server withholds the answer key and explanations until whole-set submission and checks attempt ownership using the signed-in student's account. Teacher and admin screens are not yet protected by the sign-in, and online deployment and admin AI remain future work. The student study companion and teacher note/MCQ generation call the SoC LLM. TEA-01 checks demo teacher roles and course membership on the server, but its header is spoofable and must stay development-only. Attempts are held in server memory and are lost when the backend restarts; browser reload clears the current page state.
