# README, User Guide and Developer Guide rewrite, 2026-11-12

Rewrote the root README and `docs/UserGuide.md` from the reviewer feedback, then aligned `docs/DeveloperGuide.md`.

## What changed
- **README:** purpose and features per role, then Set up (prerequisites, clone, database, backend, frontend, open the app) in chronological order, each command with a reason and macOS/Linux and Windows variants. `.env` is built by a copy-paste command with example accounts; the other settings are explained in a table. Troubleshooting, run again, clean start and a short deployment note follow. "What you can explore", test commands, the health API and the project layout moved out (to the User Guide and Developer Guide).
- **User Guide:** no feature codes. Feature tables per role link to a 25-step walkthrough (student, teacher, admin, then student feedback and admin follow-up) with copy-paste values and 45 screenshots in `docs/images/guide/`. `docs/sample-files/testing-basics.txt` is the file the teacher uploads.
- **Developer Guide:** new "Setup, configuration, tests and layout" section (settings, seeds, tests, health API, layout, documentation map); the duplicate PowerShell setup walkthrough was replaced by a pointer; stale database name and README references fixed.
- **Support changes:** `src/backend/.env.example` now points at the Compose database `learnswe` (no `createdb` step) and has clearer comments (seed lines stay empty: a test forbids committed passwords); `src/frontend/.env.example` defaults `VITE_ENABLE_DEMO_ACCESS=false`; the sample feedback form is titled "Sample course feedback"; the login demo heading and the practice hint notes no longer say "development" or "scripted demo"; the "Demo" pill on the login page shows only when the demo shortcut is on. `workflow/tools/guide-screenshots/` regenerates the screenshots by running the walkthrough.

## How it was checked
- Ran the README steps in a fresh clone against a new database: install, migrate, sample data (all three accounts seeded), backend and frontend started, both `.env` commands (bash and PowerShell, identical output, no BOM), then the whole walkthrough as a script in a real browser, twice from a clean database (45 screenshots; AI steps used the SoC LLM settings from the developer's own `.env`). Backend tests for the sample data and env example (30 passed) and 195 mocked browser tests touching the login and practice text passed; typecheck and lint clean.
- Not run: `docker compose up` on an empty volume (the existing database container was reused), a second operating system, the production deployment steps.
- The clone ran on spare ports (8100, 5273) and a separate database; on this machine Windows Application Control blocked the clone's own Python, so its backend used the repository's Python with the clone's code.
