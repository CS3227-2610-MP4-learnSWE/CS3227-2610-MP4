# Spec: TRK-03 Per-invocation metrics from Claude Code logs

Status: Approved by user in chat (2026-11-05), spec, plan and tasks, with the decisions D1 to D5 in "Open questions".

## Goal
The ADM-01 workflow experiment needs per-invocation detail the token tracker does not give today: cache behaviour, tool and file-read counts, time split, orchestrator rows and a Haiku price. TRK-03 adds these so the experiment needs no one-off scripts. It is workflow tooling in `workflow/tools/token-tracker/` (Python 3.12+, standard library only), not product code. TRK-03 has no user story; the source is the orchestrator's brief, and its requirements are traced below as R1 to R8.

## Behaviour
- R1 Pricing: `prices.json` gains Claude Haiku 5.5 (`claude-haiku-5-5`) with two per-request tiers chosen by prompt size. Existing models and flat price entries keep working unchanged. Variant model IDs of Haiku 5.5 (dated or suffixed, for example `claude-haiku-5-5-20261105` or `claude-haiku-5-5[1m]`) are priced as `claude-haiku-5-5` by one deterministic rule (see "Model ID matching").
- R2 Rebuild invocations from logs: a new command `invocations-from-logs` takes `--run-id` and one or more Claude Code session IDs and rebuilds invocations without a hand-written manifest: one invocation per subagent prompt (a resumed subagent splits per new prompt) and one `orchestrator` invocation per session for the main session.
- R3 Metrics: each invocation gets the metrics defined in "Metric definitions" below. Each is derived from the logs or is written `unavailable`; no metric is estimated. The only inference in the outputs is the labelled `likely_agent (inferred guess)` on the unattributed line (see "Unattributed usage and the likely-agent guess"); it is never part of any invocation's numbers.
- R4 Optional metadata sidecar (CSV keyed by invocation ID) adds a role label, arm, phase, revision round, trigger, start and end commit and agent-definition hash to the output rows.
- Role observability: every helper agent's role is visible. `role` is the agent type logged by Claude Code (meta `agentType`; this repo registers spec-writer, developer, test-designer and verifier). `requested_agent_type` is the short `subagent_type` named in the launching `Agent` call, or `unavailable`. `role_label` is a free label from the sidecar for when the logged type is generic (for example `general-purpose`) or `unknown`; it is shown next to `role` and never changes the invocation ID. Read `role` as what the log says, `requested_agent_type` as what the orchestrator asked for, and `role_label` as what the human says it was.
- R5 Output: a Markdown report (format `invocation-v2`) and a metrics CSV, deterministic, one row per invocation plus a run total and an unattributed-usage line.
- R6 Cross-check: per-invocation sums plus unattributed usage must equal what the existing `report` code path gives for the same sessions. A mismatch is an error: non-zero exit and nothing written.
- R7 Privacy: outputs and error messages hold only numbers, IDs, model names, roles, timestamps, branch names, folder paths and the paths of files read. No prompt, reply, tool input (other than a `Read` file path and the short `subagent_type` of an `Agent` call), tool result or file content. The `Agent` call's `description` and `prompt` and the meta `description` are never read into outputs.
- R8 Docs: `workflow/tools/token-tracker/README.md` and `workflow/usage/README.md` are updated in the same change, with the known limits.

### Terms
- Prompt size of a request = `input + cache_read + cache_write_5m + cache_write_1h` tokens (the values of one `UsageRow`).
- A request is one de-duplicated assistant message (the tracker keeps the logged line with the largest `output_tokens`; each content block of a message is logged as its own line with the same message ID).
- Request order within an invocation is the order in which each message ID first appears in the log file.
- Unavailable: the data needed is missing from the logs. It is written as the literal text `unavailable` in the Markdown and in the CSV. A blank cell means "not applicable to this row". Zero is only written when the logs show a real zero.
- Cost is "tracker list-price estimate, not billed".

### Invocation cutting (R2)
- Sessions: each session ID names `<claude-dir>/projects/<project folder>/<session ID>.jsonl` (main session) and `<claude-dir>/projects/<project folder>/<session ID>/subagents/agent-<agentId>.jsonl` (subagents, with a sibling `agent-<agentId>.meta.json`). All project folders under `projects/` are scanned. A file belongs to a session when its name matches this layout; session IDs are compared exactly.
- Orchestrator: one invocation per session for the whole main-session file, role `orchestrator`, agent ID blank, no prompt number. Its window is the whole file (this includes idle time between human turns; see known limits).
- Subagents: one invocation per prompt in each subagent file. A prompt starts at (a) the first non-meta string user line (lines before it belong to prompt 1) and (b) each string user line (meta or not) that follows the result of a `SubagentHandback` tool call. Lines are assigned to the prompt that is current in file order. A file with no non-meta string user line is one prompt. `promptId` is not used.
- Role: the subagent's `agentType` from its `.meta.json`. If the meta file is missing, unreadable or lacks a string `agentType`, the role is `unknown` and a warning goes to stderr (exit code stays 0). Characters outside letters, digits, `.`, `_` and `-` are replaced with `_` in a role used in an ID.
- Parent link: the `launched_by` field holds the orchestrator invocation ID of the session when the subagent's meta `toolUseId` equals the `id` of an `Agent` tool call in that session's main file; otherwise `unavailable`. From the same call, `requested_agent_type` holds `input.subagent_type` when it is a text of 1 to 64 characters from letters, digits, `.`, `_`, `:` and `-` only; otherwise (no call found, field absent, or any other text) `unavailable`. Orchestrator rows leave both blank. Every prompt of a resumed subagent shows the same values.
- Model ID matching (R1): a request's model ID is priced by an exact match to a key in `prices.json`; failing that, by the longest key marked `"match_variants": true` that is a prefix of the model ID and is followed in the model ID by a character that is not an ASCII letter or digit (so `-`, `[` and `.` are accepted; `claude-haiku-5-50` and `claude-haiku-5-5x` are not). Only the Haiku 5.5 entry is marked, so Sonnet 5.5 and Opus 5.5 keep exact matching and historical results do not change. Matching is case-sensitive and prefix-only: an ID that merely contains the text (for example with a provider prefix) is not priced. The observed model ID is always shown as logged.
- Invocation ID: `<run-id>-<role>-<seq>`, where `seq` counts per role across the whole run, starting at 1, at least two digits (`01`, `02`, ..., `99`, `100`). Order for numbering and for output rows: start time ascending (invocations with no start time last), then session ID, then agent ID (blank first), then prompt number; all compared as exact text after the start time. This is deterministic for the same logs, but adding an earlier invocation can renumber later ones; the sidecar must be written after the IDs are known.
- A session ID with no log file at all is an error (exit code 2).

### Unattributed usage and the likely-agent guess (R5, R6)
- Unattributed usage = usage rows (as `report` sees them) of the listed Claude Code sessions that no invocation claims, for example a log of the same session stored outside the session's folder layout. It is not an error: totals still reconcile (invocations plus unattributed equal the `report` total).
- Its numbers shown: requests, input, cache read, cache write 5m, cache write 1h, output, reasoning tokens and cost (`unavailable` if any such row is unpriced).
- `likely_agent (inferred guess)`: shown only on the unattributed line (Markdown) and row (CSV, column `likely_agent_inferred_guess`). It is an inference from log data, not a measurement, and is labelled so. It is never added to any invocation's numbers. For each unattributed row, in this order of rules, using only the row's session ID and timestamp and the invocations' start and finish times:
  1. Rule `window`: among invocations of the same session that have a start and finish time and whose start is not after the row's time and whose finish is not before it, choose the one with the shortest elapsed time (ties: the lowest invocation number in output order).
  2. Rule `nearest`: otherwise, among invocations of the same session that have times, choose the one with the smallest distance from the row's time to its start or finish (ties: the first in output order).
  3. Rule `none`: otherwise (the row has no usable timestamp, or no invocation of the session has times): `unavailable`.
  The result groups rows by guess and is written as entries `{invocation ID} (rule: {window or nearest}; requests: {k})` or `unavailable (rule: none; requests: {k})`, sorted by invocation ID (`unavailable` last), joined by `; `. With no unattributed rows it is `none` in the Markdown and blank in the CSV.

### Metric definitions (R3)
`R` is the invocation's list of requests in order; `n` its length. Time values use UTC timestamps; a log line's time is its top-level `timestamp`, and a line with a missing or timezone-less timestamp has no time. Durations are in seconds.

| Metric (CSV column) | Formula, unit, rounding | Unavailable when | Run total |
|---|---|---|---|
| Observed vs requested model (`requested_model`, `observed_models`, `model_match`) | observed = distinct `message.model` values, sorted, joined with `; `. requested = distinct top-level `requestedModel` values on the kept lines, same format. `model_match` = `yes` if every request with a `requestedModel` equals its `message.model`, `no` if any differs | `requested_model` and `model_match`: no request has `requestedModel`. `observed_models`: n is 0 | observed/requested: union; `model_match`: `no` if any invocation is `no`, else `unavailable` if any is `unavailable`, else `yes` |
| Cost split (`cost_input`, `cost_cache_read`, `cost_cache_write_5m`, `cost_cache_write_1h`, `cost_output`) | sum over requests of tokens times the price of that type for the request's tier, divided by 1,000,000; USD, 6 decimals. `cost_usd` is their sum and equals the existing per-row cost sum | any request's model or tier has no price (all five and `cost_usd` then), or n is 0 | sum |
| Reasoning share (`reasoning_share`) | sum of `reasoning_tokens` divided by sum of `output_tokens`, over the requests whose log line has `output_tokens_details.thinking_tokens` as an integer; 4 decimals | no such request, or their output sum is 0 | same formula over all invocations' such requests |
| Cache hit ratio (`cache_hit_ratio`) | `cache_read / (input + cache_read + cache_write_5m + cache_write_1h)` using the invocation's token sums; 4 decimals | denominator is 0 | same formula on run sums |
| Zero cache read after first (`zero_cache_read_after_first`) | number of requests other than the first in order with `cache_read_tokens` equal to 0; integer | n is 0 (one request gives 0) | sum |
| Cache writes after a gap (`cache_writes_after_gap`, `cache_write_tokens_after_gap`) | consider each pair of consecutive requests (in order) that both have a time. If the later request's time minus the earlier one's is strictly more than 300 seconds and the later request has `cache_write_5m + cache_write_1h` above 0, it counts once; the second column sums those writes' tokens. Pairs where either request has no time are skipped | n is 0, or n is 2 or more and no pair has both times (n of 1 gives 0) | sum |
| Context size (`context_first`, `context_max`, `context_mean`) | per request prompt size; first = first request in order, max = largest, mean = sum of prompt sizes divided by n; first and max integer, mean 1 decimal | n is 0 | first blank; max = largest invocation max; mean = run prompt-size sum divided by run requests |
| Tool calls (`tool_calls`, `tool_calls_by_name`) | number of distinct `tool_use` IDs (each counted once, however many log lines carry it) in assistant lines of the invocation's prompt; by name = `Name=count` sorted by name, joined with `; `, or `none` when there are no calls. A block without a string `id` and string `name` is ignored. `SubagentHandback` and `Agent` calls are counted like any other | never (0 is written when none) | sum; names merged |
| Failed tool calls (`failed_tool_calls`) | number of those calls whose `tool_result` block (matched by `tool_use_id`, same file) has `is_error` equal to true | never | sum |
| File reads (`files_read`, `files_distinct`, `files_repeated`, `repeated_paths`) | a file read is a tool call named `Read` with a non-empty string `input.file_path`. Path normalised: trim whitespace, replace `\` with `/`, apply `posixpath.normpath`, lowercase a leading drive letter. `files_read` = number of reads, `files_distinct` = distinct normalised paths, `files_repeated` = `files_read - files_distinct`, `repeated_paths` = paths read more than once, sorted, joined with `; ` (CSV only). `Grep`, `Glob` and other tools are not file reads. Offsets and limits are ignored, so reading two ranges of one file is a repeat | never | `files_read` sum; `files_distinct` distinct across the run; `files_repeated` = total minus distinct; `repeated_paths` blank |
| Elapsed (`started_at`, `finished_at`, `elapsed_s`) | started = earliest line time in the invocation's window, finished = latest; elapsed = finished minus started; 1 decimal | the window has no line with a time | earliest start, latest finish, difference (not a sum) |
| Active (`active_s`) | latest request time minus earliest request time (first to last request); 1 decimal; one timed request gives 0.0 | no request has a time | blank |
| Tool time (`tool_time_s`, `tool_calls_timed`) | for each tool call, the time of the first `tool_result` line for its ID minus the time of the line holding the `tool_use`, when both exist and the result is not earlier. `tool_time_s` is the sum over such calls (so it includes test-command time and any waiting for a subagent; parallel calls overlap); `tool_calls_timed` is how many calls were measured. Partly available is reported as the sum over measured calls with `tool_calls_timed` showing how many of `tool_calls` that is | `tool_calls` is above 0 and `tool_calls_timed` is 0. With no tool calls the value is 0.0 | sum of `tool_time_s` (unavailable if any invocation's is), sum of `tool_calls_timed` |
| Wait before start (`wait_before_start_s`) | this invocation's start minus the latest finish among the other invocations in the run whose finish is at or before this start; 1 decimal. A wall-clock gap, not proof that one stage depended on another | this start is missing, or no other invocation finished at or before it | blank |
| Human messages (`human_messages`) | string-content user lines that are not `isMeta: true` within the invocation's window, excluding the one prompt-start line of that window (for the orchestrator: all such lines except the first). May include injected messages that are not meta; 0 when none | never | sum |

## UI states and copy
No screen: this is a local command-line tool. Its output, messages and exit codes are fixed in `plan.md` ("CLI contract").

## Out of scope
- Codex logs: no new metrics for Codex sessions; a session ID found only in Codex logs counts as "no logs".
- Generating the `invocation-v1` manifest or changing `run-report`.
- Estimating missing data (the one labelled guess for unattributed usage excepted), live monitoring, dashboards, HTML, new dependencies.
- Reading or reporting any prompt, reply, tool result or file content, or the `description` or `prompt` of an `Agent` call.
- Checking a worktree-isolated subagent's log location (not observed).
- Changing roles or IDs from the sidecar: `role_label` is display only.
- Pricing model IDs that only contain a priced ID inside a longer text (for example a provider prefix).

## Security and AI safeguards
The tool reads local log files and writes aggregate numbers. It does not call an LLM and sends nothing off the machine. Log content is untrusted input: it is parsed as JSON only, never executed, and only the allowed fields in R7 are copied to outputs. Log text is not trusted as a path or command; only the `Read` `file_path` string and a `subagent_type` that passes the character rule are echoed, as text. Output cell text is escaped for Markdown (backslash, pipe, newline). A sidecar value is user-supplied text and is escaped the same way. Reads are limited to the given Claude directory and the given sidecar; files are written only to the chosen output paths.
- Concurrent requests (same time): not applicable: a local, single-run read of completed log files that writes two output files; running two copies at once with the same output paths is the caller's responsibility. Outputs are rendered fully in memory and written only after every check passes.
- Normalisation: session IDs, run ID, invocation IDs and sidecar IDs are compared exactly (case-sensitive, no trimming; an ID with leading or trailing whitespace is an error for session IDs and a mismatch for sidecar IDs, while sidecar cell values other than the ID are trimmed). Timestamps are parsed as timezone-aware ISO values and normalised to UTC; one without a timezone counts as missing. `Read` paths are normalised as in the metric table. Model names are compared exactly, except for the prefix rule for entries marked `match_variants` in "Model ID matching". `subagent_type` text is used as is (no trimming) and only if it passes the character rule.

## Open questions
Decided by the user (2026-11-05 feedback), no longer open:
- D1 Roles: `role` = meta `agentType`; generic or unknown types are made identifiable by the sidecar `role_label` and the Agent call's `requested_agent_type`. No `--role-map`.
- D2 Haiku model IDs: variants are priced by the prefix rule in "Model ID matching". The 100,000-token tier rule itself stays an unverified assumption, documented as a known limit.
- D3 Orchestrator time: reported as logged (elapsed includes idle time, tool time includes waiting for subagents) and documented.
- D4 Cross-check failure: exit code 1 with a descriptive message; every other error exits 2 and names its input.
- D5 Stray usage: stays on the unattributed line (not an error) with a labelled inferred `likely_agent`.

Open (genuine ambiguities, defaults given):
1. Variant matching is prefix-only. The user text allowed "contains"; a contains-rule would also price provider-prefixed IDs such as `anthropic.claude-haiku-5-5` but could match unrelated text. Default: prefix-only, as specified; say if provider-prefixed IDs occur in your logs.
2. `likely_agent` uses only the session ID and timestamps, so a stray row of a worktree-isolated subagent (location unverified) will usually be guessed as the orchestrator, because the orchestrator's window spans the session unless a subagent window is narrower and contains it. Default: as defined; it is labelled a guess.
3. `requested_agent_type` accepts only a short type name (1 to 64 characters from letters, digits, `.`, `_`, `:`, `-`). Default: anything else is `unavailable` rather than truncated.
