## UI contract
Accessible names the tests use (all except the sender line are existing ADM-02 or PR 31 names):
- Sidebar: link named `Inbox`; its badge is a `status` whose accessible name is `{n} unread inbox items`, shown as `99+` above 99, absent at 0.
- Page: level-1 heading `Inbox`; section heading `Feedback requests` (level 2, corrected after the first test run: the plan earlier called it level 1); status `Unread requests: {count}`; links named by form title; texts `Unread` or `Read` and `Not started`, `Draft`, `Completed`, `Closed`; button `Retry`; buttons `Next page`, `Previous page`; empty text `No feedback requests yet.`; loading `Loading feedback requests...`.
- Messages: heading `Messages`; status `{count} unread messages`; each message shows `From: Administrator` (option A) and the sent time. Loading `Loading messages…`, empty `No messages yet.`, list retry `Retry messages`, control `Mark as read` (copy checked against PR 31 on 2026-11-07; see the spec's Messages row).
- Form: heading is the form title; button `Submit feedback`; success `Feedback submitted. Thank you.`; closed `This form is closed.`; completed `You have already submitted feedback.`; link `Back to inbox`.

- Requests per load and per retry: Inbox page load sends one GET `/api/feedback/inbox` and one GET `/api/messaging/inbox`; the shell sends one GET `/api/messaging/unread-count` on mount. `Retry` in a section repeats only that section's read once. Opening a form sends one form GET, followed by one forced count refresh (not throttled; the 5-second throttle applies only to focus and visibility refreshes). Marking a message read sends one POST and no list re-read. The existing focus, visibility and 60-second refreshes of the badge are kept; this slice adds no polling. Tests assert counts for the inbox page and for one retry, using StrictMode-style double effects.
- Wrong role: A teacher or admin on a student inbox or form URL is redirected to their own area with replace; no inbox, form or count request for that page is sent. Direct student APIs return 403 for other roles.
- Link history: push or replace: `Inbox` link, form title links and `Back to inbox` push; Retry, pagination, mark-read and badge refreshes leave the URL; wrong-role and session-expiry redirects replace.
- No generic failure message: every failure uses the ADM-02 dictionary copy or the PR 31 section message; a network message appears only for a real transport failure; the badge shows no text on failure and keeps its last value.

### Student form presentation contract (AC15-AC18, added 2026-11-07)
Presentation only. No endpoint, schema, error code, request count, draft-saving or route change. Files: `src/frontend/src/components/FeedbackQuestion.tsx`, `src/frontend/src/pages/RecipientFeedback.tsx`, `src/frontend/src/styles.css` (student rules scoped under `.feedback-form`; the admin editor shares `.feedback-question` and `.admin-surface .feedback-question`, which stay untouched). No new module or hook; the failed-submit marker is derived in `RecipientFeedback.tsx` from existing `draft.code` and `draft.answers`.

1. Hierarchy, grouping, field appearance, actions. Page: eyebrow `YOUR FEEDBACK`, form title (the only page heading), description; one `feedback-form` panel with padding 24-28px desktop, 16-20px at 600px and below. Inside: privacy sentence, alert (if any), draft status line, then one card per question (12px radius, `--line` border, `--paper`/`--bg` surface per theme, 12-16px gap inside, 16-20px between cards). Card top row: prompt `{n}. {prompt}` left (16-18px, weight 700, `--ink`, wraps with `overflow-wrap: anywhere`), tag `Required` or `Optional` right (12-14px, `--muted`, with an outline or soft chip; text carries the meaning). Control below the row. Primary action: `Submit feedback` (contained, last); secondary: `Retry saving draft`, `Reload saved draft`, `Check submission status` as today.
2. Accessible names (tests may rely on these only). The visible prompt is a non-heading element with a stable id derived from the question id. The fieldset has no `legend`; it is named by `aria-labelledby` pointing at that element, so the prompt text exists once in the DOM and `getByText` of the prompt is not ambiguous. Roles and names: fieldset `group` named `{n}. {prompt}`; short answer and paragraph `textbox` named `{n}. {prompt}`; dropdown `combobox` named `{n}. {prompt}` (native select, first option `Choose an option`); multiple choice and linear scale `radiogroup` named `{n}. {prompt}`; checkbox `group` named `{n}. {prompt}` (the fieldset itself and the inner `role=group` are both groups with that name, as today for the fieldset and inner group; tests use `/regex/` or `.first()` as in `adm02-feedback.spec.ts` line 37 and must not assume a single match for exact names); radios named by decimal value; checkboxes and radio options named by option label. The input element carries `aria-labelledby` to the prompt id (not `label`, not `placeholder`). `Required` and `Optional` are plain text, not part of any accessible name. Inline error text `This question is required.` has an id; the control (or, for radiogroup and checkbox group, the group element) carries `aria-describedby` to it and `aria-invalid="true"` while marked.
3. Linear scale row: grid with three columns, minimum label, radios (`row` radiogroup), maximum label; labels live outside the radiogroup so radio names stay decimal values. Missing label renders an empty cell (no dash). At 600px and below the radios take the full row and the two labels sit below it, minimum left, maximum right.
4. Failed-submit marker (AC17): state `attempted` becomes true when `draft.code === "invalid_feedback_answers"` after a submit and false after a successful submit or a new form load. A question is marked when `attempted`, `q.required` and its value is blank (null, undefined, string with only whitespace after trim, empty array); this is the same predicate as the existing focus rule and must be one shared function used by both. Marker: red (existing error token or `#b3261e` light and a lighter red in dark with at least 3:1 against the card surface) 2px border on the control or option group plus the text `This question is required.` below it; the text also carries a leading non-colour cue (the words are the cue). No marker while typing or before the first failed submit. Existing focus effect moves to the first marked control; it must locate the question card by a stable class or data attribute, not by `querySelectorAll("fieldset").item(index)`, because MUI outlined inputs nest their own `fieldset` and shift the index (see spec conflict note below).
5. Fields: remove `label` and the dropdown `inputLabel.shrink` from `TextField`; no `placeholder`. Keep outlined variant, a contrasting input surface (`--paper` on `--bg` card in light; darker input surface than the card in dark), visible hover and 2px `--blue` focus ring. Scope any border reset to `.feedback-form .feedback-question` itself and never to `fieldset` descendants, so `.MuiOutlinedInput-notchedOutline` keeps its border (ui-design pitfall); the empty notch legend must not leave a gap in the border.
6. Completed and closed panel (AC18): same `feedback-form` panel padding; stack items in a grid with 12-16px gap: privacy sentence, status block (`Completed` bold, then the confirmation sentence on its own line; or `This form is closed.`), `Back to inbox` link with `justify-self: start` (left). Roles unchanged: the status is `role="status"`; `Back to inbox` is a link. No change to the draft/active-form layout other than the shared padding.
7. Theme and responsive: tokens `--ink`, `--muted`, `--line`, `--paper`, `--bg`, `--blue`, existing error colour; both themes; 320-390px: panel padding 16px, tag stacks under the prompt, radios wrap, nothing overflows horizontally; long prompts (for example 300 characters or unbroken strings) and long option labels wrap; disabled state while locked keeps text readable.
8. Focus and keyboard: tab order is prompt (not focusable), control(s), next card; after a failed submit focus lands on the first marked control (text, paragraph, select, or first radio/checkbox); visible focus ring on every control; reduced motion: no new animation.
9. Badge, refresh and requests: no badge or background refresh change. Requests per load and per retry are exactly as in the UI contract above; a failed submit is the same one POST and AC17 adds no request. Back and Forward, Refresh, Wrong role, Expired session, Backend down, Longest wait and No generic failure message are unchanged.
10. Regression and evidence: all existing `adm02-feedback.spec.ts` and `stu05-06-inbox.spec.ts` tests must pass unchanged (they locate controls by role and `{n}. {prompt}` names). Visual evidence for the verifier (ignored screenshots): form with all six question types, desktop and 390px, light and dark; failed-submit state with markers; completed and closed panels, desktop and mobile, light and dark; one long-prompt case.
