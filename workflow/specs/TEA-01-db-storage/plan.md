Status: Approved through user implementation request,2026-11-02. Developer and independent test-designer start from the same recorded contract commit. This replaces filesystem requirements in older TEA-01/notes/MCQ specs; other behaviour remains binding.

## Schema and migration

Add model `MaterialFile` registered in existing SQLAlchemy metadata, table `material_file`: `material_id UUID PRIMARY KEY REFERENCES material(id) ON DELETE CASCADE NOT NULL`; `content BYTEA NOT NULL`; CHECK `octet_length(content) BETWEEN 1 AND 10485760`. No nullable columns, implicit payload defaults, generated file key, publication field or public content URL. Material metadata remains unchanged except removal of private `storage_key`. Metadata and one content row are created in one transaction; no deferred exact-one trigger is needed. No ORM relationship may eagerly load bytes during metadata/list operations.

Migration revision `20261102_tea01_db_storage`, down_revision `20261102_tea02_mcqs`. Before any upgrade DDL, query whether material contains any row. If so raise RuntimeError with exact safe message: `Existing materials cannot be converted automatically. Configure a fresh empty database; keep the previous database and uploaded files unchanged.` No deletion, mutation, backfill, import or filesystem access. Otherwise create material_file, remove material.storage_key and its unique constraint. Do not rewrite historical migrations/live metadata snapshots.

Downgrade first checks any material rows, not just material_file rows; if present raise RuntimeError: `Cannot downgrade file storage while materials exist. Keep this database and restore the previous code, database and files instead.` Otherwise drop material_file and restore the previous nonnull unique varchar255 storage_key column on empty material. PostgreSQL transactional DDL must leave failed upgrades/downgrades and revision stamps unchanged. Fresh installs, empty downgrade/reupgrade and preservation of existing sources/notes in refused conversion are tested in separate isolated schemas.

## Upload transaction and quota

Repurpose teacher_materials/storage.py into bounded upload-byte validation, using existing dependencies/standard library only. Fixed helper contract: `validate_upload(upload: UploadFile) -> ValidatedUpload`, dataclass fields `original_filename: str`, `media_type: str`, `size_bytes: int`, `content: bytes`. This reads at most10MiB plus overflow detection; pypdf uses BytesIO, UTF-8 decoding is strict. MAX_BYTES remains10485760 for existing multipart parser reuse. Permanent storage_root/resolve_file/save_upload/remove_file paths and FILE_STORAGE_DIR requirements are removed from runtime callers. Temporary parser spooling remains closed in material_form finally.

Inside the existing authorised teacher session, validate multipart/title/topic/file before acquiring quota lock. Then execute `SELECT pg_advisory_xact_lock(32272610)` using fixed signed-bigint key32272610. Configure the teacher engine explicitly with isolation_level="READ COMMITTED"; do not inherit a database-wide repeatable-read default. Issue a fresh query AFTER lock acquisition: `COALESCE(SUM(octet_length(content)),0)` over material_file. Do not use an earlier cached aggregate/snapshot or metadata size_bytes. Reject when sum+newbytes>104857600. Hold lock through insertion/commit/rollback; it releases transactionally. Each concurrent uploader sees preceding committed bytes. This key is the test contract for lock-holding concurrency probes. All application upload paths must use it; raw administrative SQL is outside quota enforcement. No cached counter, quota table, quota endpoint or generic storage abstraction.

Create material UUID and metadata plus matching binary row, flush, serialize metadata before commit, then return201. Failure in either insert/flush/commit rolls back both; no file cleanup can delete earlier work. size_bytes is the exact content byte count. Query metadata lists only from metadata columns/models; no content fetch through lazy/eager relationships. Bytes are fetched only by authorised download/generation using material_id; no student access route.
