### Table `practice_attempt` (one row per attempt; replaces the in-memory store)

| Column | Type | Rules |
|---|---|---|
| `id` | varchar(64) PK | generated by the application, `secrets.token_urlsafe(16)`; opaque, as in STU-02 |
| `seq` | bigint NOT NULL | `GENERATED ALWAYS AS IDENTITY`, UNIQUE (constraint `uq_practice_attempt_seq`); creation order |
| `student_id` | varchar(64) NOT NULL | FK `user.id` ON DELETE CASCADE |
| `set_id` | varchar(64) NOT NULL | the code fixture's set id (no FK: sets are code) |
| `status` | varchar(16) NOT NULL | CHECK `status in ('in_progress', 'submitted')` named `ck_practice_attempt_status` |
| `answers` | jsonb NOT NULL | default `'{}'`; CHECK `jsonb_typeof(answers) = 'object'`; question id to choice id |
| `score_correct` | integer NULL | set at submission |
| `score_total` | integer NULL | set at submission |
| `key_version` | varchar(16) NULL | the answer-key version used at submission (`practice_data.KEY_VERSION`) |
| `correct_question_ids` | jsonb NOT NULL | default `'[]'`; CHECK `jsonb_typeof(correct_question_ids) = 'array'`; ids answered correctly under `key_version`, in set order; set at submission, `[]` before |
| `created_at` | timestamptz NOT NULL | default `now()` |
| `submitted_at` | timestamptz NULL | set at submission with `clock_timestamp()` |

Constraints: CHECK named `ck_practice_attempt_state`: either `status = 'submitted'` with `score_correct`, `score_total`, `key_version` and `submitted_at` all not null, or `status = 'in_progress'` with all four null and `correct_question_ids = '[]'`; CHECK named `ck_practice_attempt_score`: `score_correct is null or (score_correct between 0 and score_total)`. Indexes: `ix_practice_attempt_student_set` on (`student_id`, `set_id`, `seq`); `ix_practice_attempt_submitted` on (`student_id`, `set_id`, `submitted_at`) WHERE `status = 'submitted'`.

Rules: attempts are never deleted by the app. A submitted row is never changed again (the store refuses; the route returns 409 before). The table holds the student's own selections and a list of ids, never the answer key. Downgrade drops `practice_attempt` only. Attempts that existed only in memory are lost on deploy; no backfill.

## API endpoints

All JSON. Errors use `errors.ApiError`, rendered as `{"detail": {"code", "message"}}`.

### New: `GET /api/progress` (role `student` only)
- Dependencies: `Depends(current_user(role="student"))` (an `AuthUser`) and `Depends(auth.db.get_session)`. Request: no body, no parameters; any query string is ignored. Response header `Cache-Control: no-store` (add `/api/progress` to the path prefixes of `add_no_store` in `auth/routes.py`).
- Order of checks: 401 `unauthenticated`, 403 `forbidden`, then the work. No CSRF (GET).
- 200 body (`ProgressOut`):

```
{
  "lessons": {
    "totals": {"lesson_count": int, "completed_count": int},
    "courses": [{"id": str, "title": str, "lesson_count": int, "completed_count": int}],
    "recent": [{"lesson_id": str, "course_id": str, "title": str, "completed_at": str}]
  },
  "practice": {
    "sets": [{
      "set_id": str, "title": str,
      "attempts_submitted": int,
      "best":   {"correct": int, "total": int},
      "latest": {"correct": int, "total": int, "submitted_at": str}
    }],
    "average_latest_percent": int | null
  },
  "topics": {
    "rule": {"min_answers": 3, "weak_below_percent": 60},
    "items": [{
      "topic": {"id": str | null, "name": str},
      "answered": int, "correct": int, "accuracy_percent": int,
      "status": "needs_practice" | "on_track" | "insufficient"
    }]
  }
}
```

- `lessons.courses`: every member course (including one with zero lessons: 0 and 0), ordered by `lower(title)` then id. `totals` is the sum. Counts come from `completion_counts(db, user_id)`; titles from the shared helper `member_courses` (below). `recent`: the first 5 entries of `completed_lessons(db, user_id)` (already newest first); `completed_at` is UTC ISO-8601 with `Z` (`timestamps.utc_timestamp`). IDs are lowercase hyphenated UUID strings.
- `practice.sets`: one entry per set that has at least one submitted attempt and still exists in `practice_data.PRACTICE_SETS` (a submitted attempt on a set that no longer exists is skipped), ordered by `lower(title)` then `set_id`. `best` is the submitted attempt with the highest `correct / total` (ties: the earliest created); `latest` is the submitted attempt with the greatest (`submitted_at`, `seq`). `attempts_submitted` counts submitted attempts only. `average_latest_percent` is `floor` of the mean over the listed sets of `latest.correct * 100 / latest.total` (exact rational arithmetic, then floor); `null` when `sets` is empty. Example: one set with latest 2 of 3 gives 66.
- `topics.items`: one entry per topic with at least one answered question, ordered by status (`needs_practice`, then `on_track`, then `insufficient`), then `accuracy_percent` ascending, then `lower(name)`, then id (null id last). `answered`/`correct` are summed over the latest submitted attempt of every set (a question counts as answered when its id is a key of that attempt's `answers`, as correct when its id is in the attempt's `correct_question_ids`; only question ids that exist in the current set definition are counted). `accuracy_percent = floor(correct * 100 / answered)`. `status` comes from `progress_rules.topic_status`. `rule` is the pair of constants from `progress_rules`.
- Never present in the response: `correct_choice`, `explanation`, `key_version`, question ids or text, choices, answer maps, `attempt_id`, `student_id`.
- No data at all: `{"lessons": {"totals": {"lesson_count": 0, "completed_count": 0}, "courses": [], "recent": []}, "practice": {"sets": [], "average_latest_percent": null}, "topics": {"rule": {...}, "items": []}}`.

#### `attempt_store.py` signatures (contract)

```python
@dataclass
class Attempt:
    id: str
    student_id: str
    set_id: str
    status: str = "in_progress"                  # "in_progress" | "submitted"
    answers: dict[str, str] = field(default_factory=dict)
    score_correct: int | None = None
    score_total: int | None = None
    key_version: str | None = None
    correct_question_ids: list[str] = field(default_factory=list)
    submitted_at: datetime | None = None         # set by the store when status becomes "submitted"

@dataclass(frozen=True)
class SetSummary:
    set_id: str
    attempts_submitted: int
    best_correct: int
    best_total: int
    latest: Attempt                               # latest submitted attempt of the set

class AttemptStore(Protocol):
    def create(self, student_id: str, set_id: str) -> Attempt: ...
    def get_owned(self, attempt_id: str, student_id: str) -> Attempt | None: ...   # None if unknown or not owned
    def list_for_student(self, student_id: str, set_id: str) -> list[Attempt]: ...  # all statuses, oldest first (seq)
    def lock(self, attempt_id: str) -> AbstractContextManager[Attempt]: ...
    def submitted_summaries(self, student_id: str) -> list[SetSummary]: ...        # submitted attempts only, ordered by set_id
```

- `create`, `get_owned`, `list_for_student` keep their current meaning.
- `lock(attempt_id)` is the one change in behaviour: entering it starts a transaction, reads the attempt row with `SELECT ... FOR UPDATE` and yields a fresh `Attempt` built from that row (so the check and the change see the latest committed state). The caller changes the yielded object; leaving the block normally writes the changed fields (`answers`, `status`, score fields, `key_version`, `correct_question_ids`; `submitted_at` is set by the store to `clock_timestamp()` when `status` becomes `"submitted"` and was `None`) and commits. An exception leaves the block with a rollback, so nothing from a rejected request is saved. Unknown id: raises `ApiError(404, "attempt_not_found", "Attempt not found.")`. A row already `"submitted"` is not written back with a different status or score.
- `submitted_summaries(student_id)` runs grouped queries in the database (count, best row, latest row per `set_id`); it never loads all attempts into memory and returns nothing for `in_progress` rows.
- `DbAttemptStore` opens its own short `Session` per call from `auth.db.engine_for(load_settings().database_url)` (the same engine cache as `get_session`), so route signatures need no session. `SQLAlchemyError` is mapped to 503 by the existing handler.

#### `practice_routes.py` change (behaviour identical to today)
- `save_answers`: `with store.lock(attempt.id) as locked:` then `_require_open(locked)`, `validate_answers`, `locked.answers.update(body.answers)`, return `AnswersSaved` from `locked`.
- `submit`: inside the same kind of block: `_require_open(locked)`, `missing_questions` (422 `incomplete` raises, so nothing is saved), then set `locked.status = "submitted"`, `locked.score_correct`, `locked.score_total` from `logic.score`, `locked.key_version = KEY_VERSION`, `locked.correct_question_ids = logic.correct_question_ids(practice_set, locked.answers)`; the response `SubmitOut` is built from `locked`.
- `owned_attempt` (404 for unknown or not owned) is unchanged.

#### `practice_logic.py` addition
`def correct_question_ids(practice_set: PracticeSet, answers: dict[str, str]) -> list[str]`: ids of the questions whose answer equals the key, in set order. This module stays the only place the key is read.

#### `progress_rules.py` (contract)
```python
MIN_ANSWERS_FOR_TOPIC = 3
WEAK_BELOW_PERCENT = 60
RECENT_LESSON_LIMIT = 5
TopicStatus = Literal["needs_practice", "on_track", "insufficient"]
def topic_status(answered: int, correct: int) -> TopicStatus
    # answered < MIN_ANSWERS_FOR_TOPIC -> "insufficient"
    # correct * 100 < WEAK_BELOW_PERCENT * answered -> "needs_practice"; otherwise "on_track" (integer arithmetic only)
def accuracy_percent(answered: int, correct: int) -> int   # floor(correct * 100 / answered); 0 when answered == 0
```

#### `progress_service.py` (contract)
```python
def build_progress(
    db: Session,
    student_id: str,
    attempts: AttemptStore = store,
    sets: Mapping[str, PracticeSet] = PRACTICE_SETS,
) -> ProgressOut
```
Steps: (1) `completion_counts(db, student_id)` and `member_courses(db, student_id)`; `completed_lessons(db, student_id)[:RECENT_LESSON_LIMIT]`. (2) `attempts.submitted_summaries(student_id)`; skip summaries whose set is not in `sets`. (3) per set, tally answered and correct per `Question.topic_id` from `summary.latest`. (4) one query `select(Topic.id, Topic.name).where(Topic.id.in_(known ids))` resolves topic names; a missing, malformed or unknown `topic_id` goes to the bucket `{"id": null, "name": "General"}`. (5) apply `topic_status` and `accuracy_percent`, sort, return. Lesson tables are touched only through the two `study_lessons.progress` helpers. The `attempts` and `sets` parameters let unit tests use synthetic sets with several topics.

#### `progress_routes.py`
`@router.get("/progress", response_model=ProgressOut) def read_progress(user: AuthUser = Depends(current_user(role="student")), db: Session = Depends(get_session)) -> ProgressOut: return build_progress(db, user.id)`. The user id is `user.id` from the session only.

## Decisions
- One endpoint feeds both the Progress page and the Overview, so they cannot disagree and the Overview sends one request.
- The store keeps its interface; `lock` becomes a context manager that yields a freshly read, row-locked attempt and writes it back on a clean exit. This is the smallest change that makes the in-memory mutation pattern correct in a database and across server processes.
- Correct question ids and the key version are stored at submission, so topic statistics do not change if a key is edited later (US-TEA-04-02) and no key is read when building progress.
- Attempt summaries are aggregated in SQL so the response size and cost do not grow with the number of attempts.
- Thresholds live in one module and are returned to the client, so the page text and the calculation share one source.
- Topic names come from the `topic` table by id; the fixture holds only the id.
- Accuracy is floored for display and the weak test uses exact integer arithmetic, so a displayed 59% is always weak and a displayed 60% never is.
- No new Python or npm dependency, no new environment variable.
