# Spec: TEA-06 Teacher feedback and inbox (verification slice)

Status: Approved by the user on 2026-11-09 (Open question 1 answered: option A, redirect signed-in teachers only). Decisions 1-4 below were made by the user on 2026-11-09. Labels and endpoints checked against the code on branch `feat/tea06-feedback-inbox` on 2026-11-09. Mirrors `workflow/specs/STU-05-06/` (the student equivalent).

## Goal
From the user stories: a teacher completes open feedback forms intended for them (US-TEA-06-01), reads admin follow-up in an in-app inbox (US-TEA-06-02), opens survey requests (US-TEA-06-03) and tracks unread items (US-TEA-06-04). ADM-02 and ADM-04 already build the backend and the shared screens for both recipient roles. This slice proves every TEA-06 criterion for teachers, adds teacher-focused tests for the gaps, and removes one teacher-side defect: the signed-in route `/teacher/feedback` still shows a sample form that says "Preview only…".

## Behaviour
No new screen, table, endpoint or migration. Teachers already use, unchanged:
- `/teacher/inbox`: shared `FeedbackInbox` (section `Feedback requests`) plus shared `MessagesInbox` (section `Messages`, each message with `From: Administrator` and its sent time).
- `/teacher/feedback/{form_id}`: shared `RecipientFeedback` (form, autosaved draft, submit, closed and completed panels).
- Sidebar `Inbox` link with the combined badge (`useInboxUnread` in `Shell.tsx`; requests plus messages).
- Backend: ADM-02 `/api/feedback/inbox|forms/{id}|draft|responses` and ADM-04 `/api/messaging/inbox|unread-count|inbox/{id}/read`, all accepting roles `student` and `teacher` (contract in `plan.md`).

This slice adds: (a) a criterion-by-criterion evidence matrix (plan.md); (b) tests `test_tea06_*` and `tea06-inbox.spec.ts` only where the matrix finds a gap; (c) one frontend change, in the `/teacher` block of `App.tsx` only: a signed-in teacher visiting `/teacher/feedback` is redirected to `/teacher/inbox` with history replace; (d) `docs/UserGuide.md` and `docs/DeveloperGuide.md` corrections (teacher inbox).

### Resolved decisions (user, 2026-11-09; not re-opened)
1. Teacher role only. No change to student or admin source, tests or guide sections. Shared components (`FeedbackInbox`, `RecipientFeedback`, `MessagesInbox`, `Shell`, `useInboxUnread`) and the backend feedback and messaging modules are reused unchanged. No new endpoint, table or migration.
2. Named recipients only. "Or my teacher group" in US-TEA-06-01 and US-TEA-06-02 is an accepted deviation: admin tools target named people; there is no group targeting. It is recorded as a known limit in `docs/UserGuide.md`.
3. `/teacher/feedback` redirects to `/teacher/inbox` with history replace. Only the `/teacher` block in `App.tsx` changes; the student `/student/feedback` route and the shared `FeedbackForm` component (`pages/Inbox.tsx`) stay unchanged. Anonymous behaviour: see Open question 1.
4. `From: Administrator` is already shown for teachers by the shared `MessagesInbox`; keep it.

Also inherited from ADM-02 (not re-opened): feedback is identified, so admins see the respondent name (privacy sentence `Once submitted, your name and feedback are visible to administrators. Your unfinished draft is private.`); no retention or deletion this release.

- Requests per load and per retry: `/teacher/inbox` sends one GET `/api/feedback/inbox?limit=20&offset=0` and one GET `/api/messaging/inbox?limit=20&offset=0`; the signed-in shell sends one GET `/api/messaging/unread-count` on mount. `Retry` repeats only the failed section's read once; `Retry messages` likewise. Opening a form sends one form GET (marks the request read) followed by one forced count refresh; marking a message read sends one POST and no list re-read. Redirecting `/teacher/feedback` to the inbox sends no request for the redirect itself (the inbox then sends its normal loads). Badge refreshes on window focus and visibility (throttled to one per 5 seconds) and every 60 seconds; no other polling. Effect replay in development must not double these.
- Wrong role: a student or admin on `/teacher/inbox`, `/teacher/feedback` or `/teacher/feedback/{form_id}` is redirected with replace to `/student/overview` or `/admin/overview` (`RequireRole`), with no inbox, form or count request for that page. API calls from those roles return 403 `forbidden`.
- Link history: push or replace: the sidebar `Inbox` link, form title links and `Back to inbox` push. `/teacher/feedback` to `/teacher/inbox`, wrong-role redirects and session-expiry redirects replace. Retry, `Load more messages`, pagination, `Mark as read` and badge refreshes do not change the URL. Consequence of replace: after the redirect, Back leaves to the page before `/teacher/feedback` and does not return to it.
- Refresh: the inbox and the badge reload from the server; read state and counts equal what the teacher last saw; unsaved form answers follow ADM-02 (server draft only).
- Back and Forward: returning to the inbox issues a fresh read of both sections and the badge shows the current server count; a form opened earlier shows its current state, never cached answers.
- Expired session or logout: badge timers and requests stop, the badge disappears with the shell, and the teacher sees the sign-in screen; a 401 on any read shows `Your session has expired. Sign in again.`; after signing in again the badge and the `Read` markers come from the server (earlier reads preserved).
- Backend down: each section shows its own network message with its own retry button; the badge keeps its last value and retries silently at the next refresh.
- Longest wait before an error: 15 seconds for feedback requests and for messaging requests (timeout copy in the section rows).
- No generic failure message: every failure uses its dictionary message above; the badge never shows error text. Known inconsistency kept: the survey section says `Cannot connect to the server. Check your connection and try again.` and the Messages section says `Could not reach the server. Check your connection and try again.`; tests assert each as is.

## Out of scope
Teacher-group targeting (decision 2); a merged chronological list; a deep link from a message to a form; search or filter; email and push delivery; new routes (other than the redirect), tables or endpoints; any student or admin change; changing shared component behaviour or copy; fixing the shared-code issue in Open question 2; the sample `FeedbackForm` component and the student `/student/feedback` route; the anonymous demo inbox content.

## Security and AI safeguards
No SoC LLM call is made or changed; feedback and messages never enter AI context. Access is enforced on the server by ADM-02 and ADM-04: a teacher reads only their own inbox rows, their own form view, draft and response, and marks only their own delivery read. Another teacher's or a student's request for a teacher's form, draft, response or delivery returns the same not-found error as a missing one (404 `feedback_not_found` or `MESSAGE_UNAVAILABLE`). Role is checked on every endpoint (admin and anonymous callers are refused). The frontend redirect is a convenience only. Rendering is plain text; a message body or form text containing HTML is shown literally. New tests prove the existing rules by direct request; the slice adds no endpoint and no access rule.

- Concurrent requests (same time): two simultaneous mark-read requests for one delivery leave one read time and both succeed (idempotent); two simultaneous submissions of one form leave exactly one response and the other gets 409 `feedback_already_submitted`; a badge refresh racing a mark-read shows the old or the new count, never negative.
- Normalisation: delivery, form and response identifiers are canonical UUIDs and a malformed one gets not-found (or the existing strict-input error), as in ADM-02 and ADM-04; account IDs and roles come only from the session, never the client.
