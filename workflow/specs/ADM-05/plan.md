# Plan: ADM-05 User and access management

Status: Approved by user instruction to implement the agreed requirements, 2026-11-06.

## Data model
Add an additive Alembic migration after the actual current single head; never edit historical revisions. Add user.access_status varchar with NOT NULL default 'enabled', CHECK enabled/disabled/archived, and user.archived_at nullable timestamptz (populated on archive, never cleared). Existing accounts remain enabled. Keep one role in existing User.role, with no update API. Preserve unique normalised email; archived rows retain email/hash linkage but cannot authenticate. Reuse existing Course, CourseMembership, auth_session, lesson_completion and authored-record references. CourseMembership composite identity (course_id,user_id) remains the only course-access store: student role means enrolment, teacher role means management. No role-agnostic admin membership grants. Course creation uses UUID identity and existing required timestamp defaults. In the same transaction, create exactly one Topic with its own UUID, course_id equal to the new course and name General. Commit both or neither; existing courses/topics are not backfilled or changed. This default makes the existing teacher publication workflow usable without adding a topic-management feature. Index status/role where useful. Downgrade refuses if non-enabled accounts exist, to avoid silently reactivating archived/disabled users.

## API endpoints
Every endpoint below under /api/admin uses real cookie authentication through current_user(role="admin"); all unsafe methods require shared CSRF/Origin validation. Anonymous 401, wrong role 403, malformed identifiers/body/query 422, missing entity 404. No demo identity headers. Use existing errors.ApiError envelope {"detail":{"code":str,"message":str}}. Every success/error response carries Cache-Control: no-store. Auth/session rejection precedes input validation.

Public shapes (all fields required unless stated):
- Account: {id:str,email:str|null,display_name:str,role:"student"|"teacher"|"admin",status:"enabled"|"disabled"|"archived"}. Never expose passwords/hash/session metadata.
- Course: {id:str UUID,title:str}.
- AccountDetail: {account:Account,courses:Course[]} with courses sorted title case-insensitively then id.
- AccountPage: {accounts:Account[],total:int,page:int,page_size:int}.
- CourseList: {courses:Course[]} sorted title case-insensitively then id.

| Method and path | Exact input | Success | Additional errors |
|---|---|---|---|
| GET /api/admin/accounts | query search optional trimmed literal substring max 200; role optional student/teacher/admin; status optional enabled/disabled/archived/all default enabled; page integer >=1 default 1; page_size 1..100 default 20; reject unknown query fields | 200 AccountPage; sorted lower(display_name), id; search matches name or email; out-of-range page returns empty accounts and correct total | validation_error |
| POST /api/admin/accounts | body exactly {display_name:str,email:str,password:str,role:enum}; display_name trimmed 1..80, shared email/password validation; confirm password is client-only | 201 Account, enabled, no memberships, u- UUID hex ID | 409 email_exists including archived accounts; 422 validation_error |

| PUT /api/admin/accounts/{user_id}/status | body exactly {status:"enabled"|"disabled"} | 200 Account, idempotent; enabling does not recreate sessions | 409 self_change for self-disable; 409 last_admin; 409 account_archived |
| POST /api/admin/accounts/{user_id}/archive | no body (empty request) | 200 Account; repeated archive returns archived unchanged; delete all sessions and memberships atomically | 409 self_change; 409 last_admin |
| PUT /api/admin/accounts/{user_id}/courses/{course_id} | no body (empty request) | 200 AccountDetail; idempotent grant; allowed for enabled/disabled student or teacher | 409 account_archived; 409 invalid_assignment for admin |
| DELETE /api/admin/accounts/{user_id}/courses/{course_id} | no body (empty request) | 200 AccountDetail; idempotent removal; validate account/course exist | 409 account_archived; 409 invalid_assignment for admin |
| GET /api/admin/courses | no query parameters | 200 CourseList | validation_error |
| POST /api/admin/courses | body exactly {title:str}; trim 1..200 characters | 201 Course; duplicate titles allowed; atomically creates one default General topic in that course (response shape unchanged) | 422 validation_error |

Invalid enum, extra fields (including role/status on unsupported endpoints), password, email and missing fields produce 422 validation_error. Unsupported role-changing route does not exist. Map duplicate email transaction races to email_exists. Missing/inactive actor after obtaining mutation lock is 401 unauthenticated, preventing revoked admins acting after waiting on another mutation. Existing login returns its usual indistinguishable invalid_credentials for disabled/archived users. Existing valid sessions for inactive users give 401 unauthenticated and do not reach endpoint logic. CSRF failures keep existing csrf_failed code.

## UI contract
Use exact controls and catalogue copy from spec. Account row Manage account buttons must have contextual accessible names 'Manage account NAME' to distinguish rows. Selected account displays name/email/role/status text; enabled account offers Disable account, disabled offers Enable account, both offer Archive account; archived details have no mutable controls and text 'This account is permanently archived.'. Confirmation dialog description names affected account and course where relevant; archive explicitly says permanent and retained history. Every form label is programmatically associated. Course select options use course title; assigned courses show title and a per-row Remove course access button with contextual accessible name 'Remove course access TITLE'. Teacher/student account details explain management assignment/enrolment respectively; admin details say 'Administrators do not receive course assignments.'. Role filter options All roles, Student, Teacher, Admin; Status filter Enabled, Disabled, Archived, All statuses. Account role options Student, Teacher, Admin; default Student. Search applies only on Search submit and resets page 1; filters also reset page 1 and load once; Previous/Next disabled at boundaries. Dialog title accessible role dialog name from spec, confirm/cancel buttons exact. During write disable corresponding controls; no optimistic mutation. Error alerts contain catalogue copy; success role status.

- Requests per load and per retry: /admin/users one accounts GET plus one courses GET; selecting row one account-detail GET; /admin/courses one courses GET. Retry repeats failed request only. Mutation one write then one affected list and selected detail refresh if needed; grants/removals use returned detail rather than another GET. Account creation refreshes accounts once; course creation refreshes courses once. No duplicate StrictMode reads, no cross-session in-flight sharing.
- Wrong role: shared guard redirects wrong-role users to own area before API calls; demo displays sign-in notice with no real data; mid-session 401 clears UI.
- Link history: push or replace: Users and Courses links push; role/login redirects replace; filters, selection, pagination and dialogs change no URL.
- Refresh: re-fetch and restore default filter/selection state, never a password.
- Back and Forward: render correct route and refetch, never stale cross-session data.
- Expired session or logout: clear confidential/secret state; existing login redirect/SignInNotice behaviour.
- Backend down: network alert with Try again for failed reads; retain entered values for explicit write retry.
- Longest wait before an error: 10 seconds per request via shared client.
- No generic failure message: exact error-code catalogue in spec; no network wording for HTTP errors.

## Decisions
User decisions are recorded in spec and revised stories. No role-change feature. Student memberships and teacher assignments share existing storage and differ by immutable role. Admins can create courses and all account types, but courses cannot be assigned to admins. Admin-set passwords intentionally have no compulsory-change flow. Archive is retention, not erasure. Routine schema bounds/query defaults/UI copy are fixed above. Deployment and email delivery are not part of this change.
