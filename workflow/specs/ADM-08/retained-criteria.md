### Error dictionary (ADM-02; exact; used by the Forms and Responses tabs and the respondent pages)
Validation priority: auth, role, record visibility, state/version, input validation. For draft PUT and submission: visibility, closed (C04), already submitted (C05), draft version (C06), then answer validation (V11 for draft, V10 for submission). The same lock order is used for autosave, submission and close. Unknown or missing top-level body keys (including a forged `user_id`) and invalid `version`/`draft_version` scalar types use V01 on draft PUT and submission POST; invalid answer containers/items/types, foreign ids and answer-size limits use V11 (draft) or V10 (submission); the body byte cap stays V08. V01 concerns the top-level request object; a question's invalid required flag (for example the string `"true"`), prompt, type, identifier or object shape uses V03; V04 and V05 stay for choices and scales. Boolean strings are rejected, never coerced. A forged unpublished form id is E03 to respondents, never C02. Validation metadata: `details` is optional in the error envelope and this release emits none; clients must not depend on it.

Standard entries (unchanged by ADM-08 except that admin URLs are the hub URLs above):
- Requests per load and per retry: one request for each list, detail, response list, response detail or recipient form load; zero for a new draft. An existing editor sends one form read and one association-options read; a new editor one association-options read (fetched once, not per keystroke). Audience review sends one paged audience read; explicit search, role or page changes send one each; review confirmation makes no read. Each save, publish, close or submit sends one mutation, and its response updates the page with no automatic re-fetch. The recipient form GET marks its request read atomically (no second mark-read request). Each `Retry` repeats only the failed request once. Development effect replay does not duplicate reads. Recipient autosave: one PUT after 1000 ms idle, coalesced serial writes, one flush before normal in-app navigation, zero writes on hydration, manual retry after failure; submission waits for an in-flight save, cancels the pending debounce and posts the current answers once. No polling or automatic retries.
- Wrong role: admin routes redirect students and teachers to their own authenticated landing area using replace and send zero ADM-02 requests; recipient routes redirect admins to their landing area and student/teacher cross-role paths to their own landing area, using replace and sending zero feature requests. Direct backend requests stay forbidden (E02).
- Link history: push or replace: sidebar links, list-title links, `New feedback form`, `Review responses`, response links and `Back to inbox` push. The first successful create replaces the new-form URL with the saved detail URL. Save, publish, close, submit, dialogs, pagination and filtering do not change the URL. Authentication redirects replace.
- Refresh: saved data is reloaded with the request counts above, including the current recipient's saved draft answers. Admin unsaved editor changes reset (the existing unsaved-changes warning stays). Respondent draft answers live on the server, never in browser storage. `Draft saved. You can return to finish later.` appears only after acknowledgement; native beforeunload protection applies while a save is pending or failed. Unacknowledged edits cannot be guaranteed after abrupt termination.
- Back and Forward: re-entering a route reloads the current authorised state once; private response content is never restored from client cache. List pagination resets to the first page. Closed or submitted forms show the current terminal state.
- Expired session or logout: abort pending feature requests and timers, clear loaded private data and unsent fields, and replace with sign-in through the existing flow. Acknowledged response drafts stay on the server and restore only for the same authorised recipient. Logout is never blocked to finish a save. 401 message is `Your session has expired. Sign in again.` A late response never repopulates data after an account change.
- Backend down: `Cannot connect to the server. Check your connection and try again.` with `Retry` on reads; unsent fields stay on mutations; uncertain admin writes or submissions are reconciled through the reload controls before another write. Draft-save failures offer `Retry saving draft`; stale-version protection prevents overwrite. A timed-out mutation is never asserted to have failed to commit.
- Longest wait before an error: 15 seconds per feature request, then abort and `The request timed out. Check the current form before trying again.` Pending mutation controls are disabled; recipient navigation waits for draft flushing. After an uncertain admin save, publication, close or submission, an explicit reload discovers server state before another state-changing action; a draft PUT permits manual retry guarded by its version (C06 needs an explicit reload).
- No generic failure message: each failure uses the dictionary; network copy is reserved for transport failures; an unexpected HTTP 500 or unknown status uses `The feedback service encountered an error. Try again later.`, never network copy.

### ADM-03 failure messages (exact)
No catch-all wording exists ("Something went wrong", "An error occurred", or "Try again later" with no reason). `{step}` is "batch {k} of {n}" for a map call (internal-error phrase "processing batch k of n"), "merging themes" for the reduce call, "reading the responses" or "computing the statistics" before the AI starts, "starting the AI step" for an exception before the first call, or "deleting the analysis" or "deleting the response" for a delete. The stored failure record keeps `code`, `message`, `step` and `details`.

Request failures (create and read endpoints; the UI shows the message exactly):
- `invalid_request`: "The analysis request is malformed: {reason}." with reason one of "form_id is not a valid id", "request_id is not a valid id", "response_ids must be a list of ids", "response_ids contains a value that is not a valid id", "send either response_ids or select_all, not both", "send response_ids or select_all set to true", "select_all must be true", "expected_count must be a whole number from 0 to 500", "expected_count is only allowed with select_all", "unknown field {name}", "the request body is larger than 256 KiB".
- `selection_required`: "No responses are selected. Select at least one response, or use Select all, then generate the analysis."
- `no_responses`: "This form has no submitted responses, so there is nothing to analyse."
- `too_many_responses`: "You selected {n} responses, but one analysis can cover at most 500. Select fewer responses."
- `nothing_to_analyse`: "The {n} selected responses contain no answered questions, so there is nothing to analyse."
- `form_not_found`: "That form is not available. It may have been deleted. Choose another form."
- `response_not_found`: "{k} of the {n} selected responses are not available for this form (they may have been deleted or belong to another form). Reload the list and select again."
- `analysis_in_progress` (409): "Another analysis started {s} seconds ago is still running its AI step. A running AI step finishes or fails within 780 seconds. Wait for it, then generate again."
- `analysis_not_found`: "That analysis is not available. It does not exist or is not in your history."
- `analysis_running` (409, delete only): "This analysis cannot be deleted yet: its AI step has been running for {s} seconds. It finishes or is marked interrupted within {r} seconds (the limit is 780 seconds). Delete it after that."
- Delete-specific page messages: 404 on delete: "This analysis was already deleted or is not in your history. The list has been refreshed."; network failure: "Could not reach the server while deleting the analysis. It was not confirmed as deleted. Press Delete permanently to try again."; 15 s abort: "The server did not answer within 15 seconds while deleting the analysis. It may or may not be deleted. Press Delete permanently again; if it was already deleted you will be told so."; success status: "Analysis deleted. The original feedback responses and forms were not changed."
- `evidence_not_found`: "This response cannot be shown. It was deleted, or the reference is not part of this analysis."
- `internal_error` (500, create or read): "An unexpected server error occurred while {step}. The cause was not an invalid request. Reference {ref} identifies it in the server logs."

Error copy (role `alert`, exact):
- Empty or too long subject: `Enter a subject between 1 and 120 characters.`
- Empty or too long body: `Enter a message between 1 and 5000 characters.`
- No selection or too many: `Select between 1 and 500 recipients.`
- 401: `Your session has expired. Sign in again.` (clear private state and replace navigation to login.)
- 403: `Only admins can send messages.` (clear private state and replace to own role area.)
- 404 response or recipient: `This feedback recipient is unavailable.`
- 404 inbox message: `This message is unavailable.`
- 404 preview: `This message review is unavailable. Review the message again.`
- 409 recipient change: `The audience has changed. Review the recipients again before sending.`
- 409 expired preview: `This review has expired. Review the message again.`
- 422 invalid request other than field errors: `Check the message and audience, then review again.`
- 429: `Too many messaging requests. Wait a minute and try again.`
- 403 CSRF: `Your security session has expired. Refresh the page and try again.` (fields kept; no automatic retry.)
- 413: `The message request is too large. Shorten it and try again.`
- 500: `Messaging encountered an error. Try again.`
- 503: `Messaging is temporarily unavailable. Try again.`
- Network: `Could not reach the server. Check your connection and try again.`
- Timeout: `The request timed out. Try again. If you were sending, retry this review to check delivery.`
- Missing or expired recovered review: the exact alert above plus button `Start a new message`.

Standard entries (ADM-04 composers; hub URLs per the route table):
- Requests per load and per retry: a review query replaces composer loading with exactly one preview GET; otherwise the response composer sends exactly one recipient GET and the announcement composer exactly one first-page recipients GET (default Students, All active users). Each list search (debounced 300 ms), page or role change triggers exactly one GET; no hidden count call. Selecting users and typing text send no request. Review sends exactly one preview POST; confirm send exactly one send POST. Retry repeats exactly the failed request, never automatically. Development StrictMode does not duplicate load requests. The inbox sends exactly one messages GET on mount, one per load-more or retry, and one read POST per click. The navigation badge: one `GET /api/messaging/unread-count` once per authenticated student/teacher shell mount (deduplicated under StrictMode), every 60 seconds while visible, and on focus or visibility return with a 5-second minimum spacing; not repeated for ordinary route navigation; list loads and successful reads update the badge locally without another GET; opening a feedback form requests one count refresh after its successful read; in-flight refreshes coalesce; no calls for anonymous or admin shells; background failures keep the last known count and an initially unavailable count stays hidden.
- Wrong role: redirect to the own role home using replace with no messaging API request; anonymous users replace to login. The server still enforces roles.
- Link history: push or replace: entry links push composer URLs; `?review={preview_id}` is set by replace; edit removes that query by replace; the receipt keeps it; `Back to feedback` pushes the original response URL; `New announcement` resets local state at the same URL; login and role redirects replace.
- Refresh: a missing or expired recovered review shows its exact alert and button `Start a new message`, which clears the review query by replace and loads the empty composer once. Editing a recovered valid review restores subject, body, audience mode and selected ids with one eligibility GET and no preview creation or send. After preview creation, the returned preview is used directly with no extra GET. A composer without a review query reloads empty fields and refetches recipients. A review query loads the durable preview or sent receipt with one GET and never sends automatically. No unsent content is stored in browser storage. After an uncertain send, refresh restores the same preview or receipt and a retry uses the same id.
- Back and Forward: navigation remounts an empty composer without a review query or restores that exact durable preview or receipt with a review query; one corresponding GET, no automatic send. Requests are aborted and stale completions ignored when the route or account changes.
- Expired session or logout: clear the composer, selections, preview and receipt immediately; never show previous-account content or accept a stale response after another login.
- Backend down: exact network or 503 copy and `Retry`; current local text is preserved while the account stays the same.
- Longest wait before an error: 15 seconds per request, including send; abort and show the timeout copy. No uncontrolled retry.
- No generic failure message: all failures map to the exact copy above; network copy is reserved for network failure.
