## Data model
Reuse the existing PostgreSQL schema and Alembic revisions. No new product tables. Development and production use separate empty databases and users; DATABASE_URL uses postgresql+psycopg:// and provider-required TLS. Original uploads remain database-backed. Startup migration uses one fixed PostgreSQL advisory-lock key 3227261001 on a dedicated connection, shared by both manual and startup migration commands. Lock acquisition deadline 60 seconds; failure exits nonzero before HTTP startup. Never automatically seed or downgrade. Document backup and tested restore before later production schema changes.

## API endpoints
Existing auth/learning/admin endpoints retain contracts. No website API.

| Method/path | Access | Request | Response/error |
|---|---|---|---|
| GET /api/health | Public | No body | Existing 200 {"status":"ok"}; process liveness only |
| GET /api/health/ready | Public | No body | Existing 200 {"status":"ready"}; preserve process-readiness semantics |
| GET /api/health/database | Public | No body | 200 {"status":"ready"} after SELECT 1; database unavailability or timeout returns 503 {"status":"unavailable"}; no SQL/host/credentials in body; total DB check deadline 5 seconds; never calls AI |
| GET or HEAD /assets/{path} | Public | Static path | Actual built asset or 404; never SPA fallback |
| GET or HEAD /{path} | Public | Client route accepting text/html | Built index.html for extensionless routes outside api/assets; missing build or other files return 404, never filesystem listing; HEAD returns no body |

/api and /api/... are always reserved. Unknown API paths/methods retain framework JSON 404/405 and existing error handlers. Non-GET/HEAD frontend requests return 405. Traversal, including encoded dot segments, cannot read outside build root. Requests without text/html acceptance do not receive SPA fallback (browser */* is acceptable only for the root /). Register fallback after every API route. Existing auth middleware and protected routes remain active.

### Contract clarification - 2026-11-13
The approved behavior is unchanged. Independent test design identified missing dependency seams before implementation of affected pieces. `deployment.health` exposes imported `engine_for(url: str) -> Engine` from `auth.db` and `load_settings()` for isolated health tests; database_health() uses these dependencies and returns the API response contract above. At most one probe is in flight, and callers return unavailable within five seconds even if a driver blocks. `deployment.start.migrate(database_url: str) -> None` performs advisory-locked migrations; its module exposes SQLAlchemy `create_engine` and Alembic `command.upgrade` for dependency substitution. Constants `MIGRATION_LOCK_KEY = 3227261001` and `LOCK_TIMEOUT_SECONDS = 60` pin the lock contract. It raises on failure; main() converts failure to fixed redacted diagnostics/nonzero exit and never executes Uvicorn until migrate succeeds. Tests may patch these module dependency names without inspecting implementation. This clarification adds no endpoint, user behavior or hosting scope.

### Deployment automation testing interface - 2026-11-13
`scripts/deploy_render.py` exposes `request_json(url: str, token: str, data: dict | None = None) -> dict` (GET without data; POST JSON with data), `verify_commit(sha: str) -> None`, and `main() -> None`. verify_commit uses GITHUB_REPOSITORY/GITHUB_TOKEN and subprocess.run to fetch deploy/production-pages and verify SHA reachability on origin/deploy/production-pages plus successful push CI for that exact branch/commit. main reads DEPLOY_COMMIT, RENDER_API_KEY, RENDER_SERVICE_ID and invokes verify_commit before any Render deployment call; a returned deploy.commit.id differing from the requested SHA fails closed. Only a verified public URL is printed. Tests may replace module request_json, subprocess.run, os.environ and time.sleep. HTTP implementation imports urllib.request.urlopen as module urlopen. Invalid/missing CI, unreachable deployment-branch SHA, provider failure or commit mismatch cannot be reported as successful deployment. The migration helper additionally rejects a database_url unequal to validated configured DATABASE_URL, ensuring its advisory lock covers Alembic's configured target. These internal interfaces clarify the approved behavior without changing scope.

### Dedicated-branch CI waiting contract - 2026-11-13
The amended source is a fixed module constant DEPLOYMENT_BRANCH = "deploy/production-pages" in scripts/deploy_render.py, not an environment-controlled arbitrary branch. Existing verify_commit(sha: str) -> None retains immediate fail-closed semantics: validate full 40-hex SHA, fetch that branch, require git merge-base --is-ancestor sha origin/deploy/production-pages, and require a successful CI push run for that exact SHA and branch. It must reject otherwise-green master/other-branch, PR, failed/pending and wrong-SHA runs. Existing request_json(url, token, data=None) seam remains unchanged. CI URL is the repository actions/workflows/ci.yml/runs endpoint with head_sha, event=push, branch=deploy/production-pages and per_page=100 query parameters; percent-encoding the slash in the query value is allowed.

Add public wait_for_ci(sha: str) -> None, constants CI_WAIT_TIMEOUT_SECONDS = 900 and CI_POLL_INTERVAL_SECONDS = 10. It validates SHA syntax and deployment-branch ancestry before polling, using the same branch validation as verify_commit. Poll only the ci.yml endpoint above through request_json; tests may replace request_json, subprocess.run, time.monotonic/time.sleep and constants. Ignore unrelated SHA/branch/event runs. Select the newest eligible run by numeric id (the API returns id); a completed success returns, a completed non-success fails immediately with ValueError("CI failed for the selected deployment commit."). Missing, queued, requested, waiting, pending or in-progress eligible CI sleeps no longer than the smaller of ten seconds and remaining deadline; expiry raises ValueError("CI did not pass within 15 minutes."). Check the deadline before each HTTP request and before sleeping. Each existing request_json network operation retains its 30-second timeout, so the CI phase wall-clock maximum is 930 seconds including a final in-flight request; no uncontrolled retries. HTTP/auth/malformed-response errors fail closed rather than become success or expose response bodies. No Render call occurs in wait_for_ci. A prior older success does not override the newest eligible failure or pending run during waiting.

main() reads WAIT_FOR_CI: only the literal "true" enables wait_for_ci before its unconditional verify_commit call; unset/false keeps existing immediate verification. After a successful wait, verify_commit runs again before any Render request to retain exact-SHA/ancestry checks. The previously fixed provider polling/deploy-id/commit mismatch and redacted CLI errors are unchanged. Existing main tests remain applicable with WAIT_FOR_CI unset. New independent tests must cover delayed success, no-run timeout, pending timeout, terminal failure/cancel, wrong-branch/event/SHA exclusion, newest-run selection, ancestry failure, invalid SHA, bounded sleeps and the prohibition on Render requests before success.

Environment policies: development allows branch deploy/production-pages and tags deploy-development-*; production allows only tags deploy-production-*; github-pages allows branch deploy/production-pages and tags publish-site-*. Keep custom branch policies enabled, remove the earlier master allowance, and preserve existing secrets/protection settings. Only trusted maintainers should create release/publication tags.
