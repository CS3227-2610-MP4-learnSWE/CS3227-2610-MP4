### Table `published_lesson` (immutable snapshot; written by TEA-03 publication, read here)

| Column | Type | Rules |
|---|---|---|
| `id` | UUID PK | generated by the application (`uuid4`) |
| `course_id` | UUID NOT NULL | FK `course.id` |
| `topic_id` | UUID NULL | composite FK (`topic_id`, `course_id`) to `topic` (`id`, `course_id`) (constraint exists as `UniqueConstraint("id","course_id")`); NULL means "General" |
| `title` | varchar(200) NOT NULL | CHECK `char_length(title) between 1 and 200` |
| `content` | text NOT NULL | CHECK `char_length(content) between 1 and 2000`; plain text |
| `source_draft_id` | UUID NULL | FK `study_note_draft.id` ON DELETE RESTRICT, so a draft with a published lesson cannot be deleted (the teacher delete route returns 409 `draft_in_use`); traceability only, never read by student routes |
| `published_by` | varchar(64) NOT NULL | FK `user.id` |
| `published_at` | timestamptz NOT NULL | default now() |
| `withdrawn_at` | timestamptz NULL | NULL = visible; set = hidden from students |

Constraints and indexes: `UniqueConstraint("id","course_id", name="uq_published_lesson_id_course")` (target of the completion FK); index `ix_published_lesson_course` on (`course_id`, `withdrawn_at`).

### Table `lesson_completion` (one row per student and lesson; the record STU-04 reads)

| Column | Type | Rules |
|---|---|---|
| `user_id` | varchar(64) NOT NULL | FK `user.id` ON DELETE CASCADE; part of PK |
| `lesson_id` | UUID NOT NULL | part of PK |
| `course_id` | UUID NOT NULL | copied from the lesson; composite FK (`lesson_id`, `course_id`) to `published_lesson` (`id`, `course_id`) |
| `completed` | boolean NOT NULL | current state |
| `completed_at` | timestamptz NULL | set when `completed` becomes true (kept if it is already true); NULL when false. CHECK `completed = (completed_at is not null)` named `ck_lesson_completion_state` |
| `updated_at` | timestamptz NOT NULL | default now(); set on every write |

PK (`user_id`, `lesson_id`). Indexes: `ix_lesson_completion_user_course` on (`user_id`, `course_id`); `ix_lesson_completion_lesson` on (`lesson_id`) (for TEA-05 later).

Rules: rows are never deleted by the app; "incomplete" is `completed = false` (row kept, `completed_at` NULL). A row exists only after the student first marks the lesson; absence means incomplete. Completion never stores answers, scores or time spent.

Downgrade: drop `lesson_completion`, then `published_lesson`. Nothing else changes.

### Meaning for STU-04 (fixed here so the dashboard needs no schema change)
- Lessons completed = rows with `completed` true whose lesson has `withdrawn_at` null and whose course the user belongs to.
- Total lessons = non-withdrawn `published_lesson` rows in the user's member courses.
- STU-04 must call `completion_counts` and `completed_lessons` below, not query the tables.

## API endpoints

All under `/api/study`, JSON, all `student` role only through `Depends(current_user(role="student"))` (reuse `student_identity.require_student` is NOT used because it returns only the id; use `current_user` directly to also have the `AuthUser`). One SQLAlchemy session per request from `auth.db.get_session`. Errors use `errors.ApiError`, rendered as `{"detail":{"code","message", ...}}`. Responses carry `Cache-Control: no-store` (the existing `add_no_store` middleware applies to `/api/auth/*` only; the study router adds the header itself, for example with a small router dependency or a response header, since the data is private).

Order of checks on every endpoint: 401 `unauthenticated`, 403 `csrf_failed` (PUT only), 403 `forbidden` (role), 422 path id, 404 `not_found` (record or course not visible), 422 body, then the work.

Common objects:
- `LessonSummary`: `{"id": str, "title": str, "excerpt": str, "completed": bool}`. `excerpt` = content with every run of whitespace replaced by one space, stripped, first 160 code points (no ellipsis added).
- `TopicRef`: `{"id": str | null, "name": str}`; null topic is `{"id": null, "name": "General"}`.
- Timestamps are UTC ISO-8601 with `Z`. UUIDs are lowercase hyphenated strings.

| Method and path | Request | Success |
|---|---|---|
| `GET /api/study/courses` | none | 200 `{"courses":[{"id":str,"title":str,"lesson_count":int,"completed_count":int}],"totals":{"lesson_count":int,"completed_count":int}}`. Only courses the user is a member of, ordered by `lower(title)`, then id. Counts per the STU-04 meaning above. A member course with no lessons appears with 0 and 0. No courses: `{"courses":[],"totals":{"lesson_count":0,"completed_count":0}}` |
| `GET /api/study/courses/{course_id}/lessons` | none | 200 `{"course":{"id":str,"title":str},"topics":[{"id":str\|null,"name":str,"lessons":[LessonSummary]}]}`. Non-withdrawn lessons only. Topics ordered by `lower(name)`, then id, with the null topic ("General") last; topics with no visible lessons are omitted. Lessons inside a topic ordered by `published_at`, then id (ascending). At most 500 lessons are returned (the first 500 in that overall order); no pagination |
| `GET /api/study/lessons/{lesson_id}` | none | 200 `{"id":str,"course":{"id":str,"title":str},"topic":TopicRef,"title":str,"content":str,"published_at":str,"completed":bool,"completed_at":str\|null}` |
| `PUT /api/study/lessons/{lesson_id}/completion` | body exactly `{"completed": bool}`; strict boolean (a string, number or null is 422); unknown or missing fields are 422 | 200 `{"lesson_id":str,"completed":bool,"completed_at":str\|null,"course":{"id":str,"lesson_count":int,"completed_count":int}}` reflecting the stored row after the write. Idempotent: the same body twice gives the same state; `completed_at` keeps its first value while the state stays true |

There is no endpoint that takes a user id, no list-all-lessons endpoint, and no delete.

### Error codes

| Status | `detail.code` | Message | Condition |
|---|---|---|---|
| 401 | `unauthenticated` | Sign in to continue. | no, unknown or expired session (from `current_user`) |
| 403 | `forbidden` | You do not have access to this. | teacher or admin session |
| 403 | `csrf_failed` | (existing SHR-01 text) | PUT without a valid `X-CSRF-Token` or with a disallowed `Origin` |
| 404 | `not_found` | Lesson not found. | lesson id unknown, withdrawn, a draft id, or in a course the user is not a member of (identical body for all) |
| 404 | `not_found` | Course not found. | `GET /courses/{id}/lessons` for a missing course or non-member (message from `require_course_member`) |
| 422 | `validation_error` | Provide a valid request. | invalid path UUID, or invalid body; the extra field `fields` is a list of field names (body only, never values). FastAPI's default 422 body is acceptable for an invalid path UUID; tests check status 422 only for paths |
| 503 | `service_unavailable` | The service is unavailable. | database error (existing handler); never falls back to other data |

Upsert statement (the only write; one SQL statement so concurrent requests cannot create two rows):
`INSERT INTO lesson_completion (user_id, lesson_id, course_id, completed, completed_at, updated_at) VALUES (:u, :l, :c, :done, CASE WHEN :done THEN now() END, now()) ON CONFLICT (user_id, lesson_id) DO UPDATE SET completed = EXCLUDED.completed, completed_at = CASE WHEN EXCLUDED.completed THEN COALESCE(lesson_completion.completed_at, EXCLUDED.completed_at) END, updated_at = now() RETURNING ...`. Use SQLAlchemy `postgresql.insert(...).on_conflict_do_update(...)`.

## UI contract

Accessible role and name that tests use (exact). Copy for every state is in the spec's "UI states and copy"; this section fixes controls.

Materials page `/student/materials`:
- Heading level 1 "Small lessons. Lasting understanding."
- Loading: element `role="status"` with text "Loading study materials…".
- Error: element `role="alert"` containing the message; button "Try again" where the spec lists one (role button, name "Try again"). Demo-mode 401: the SignInNotice alert with link "Go to sign in".
- Course: native `<select>` with label "Course" (role combobox, name "Course"; options named by course title). Always rendered once courses have loaded, even for one course.
- Topic filter: buttons named "All topics" and each topic name (for the null topic "General"); the active one has `aria-pressed="true"`, the others `"false"`.
- Search: text field named "Search materials" (role textbox); filters lesson titles case-insensitively, client side.
- Count: text "N of M lessons complete" (for example "1 of 2 lessons complete") for the selected course, from the lessons response (`completed` flags), not the courses call.
- Lesson card: role link; accessible name contains the topic name, title, excerpt and status text; status text is exactly "Complete" or "Start learning". Link target `/student/materials/<lesson id>`.
- Empty states: headings level 3 with the exact titles in the spec.
- URL: `?course=<course id>`; unknown or non-member course id in the query is ignored and the first course is selected (no error).

Lesson page `/student/materials/<lesson id>`:
- Loading: `role="status"` "Loading lesson…".
- Link "All study materials" (role link) to `/student/materials?course=<course id>`; before the lesson has loaded the link goes to `/student/materials`.
- Heading level 1 = lesson title; eyebrow text `<TOPIC NAME UPPER-CASE> · <COURSE TITLE UPPER-CASE>`.
- Content: element `role="region"` with `aria-label="Lesson content"`; text shown with `white-space: pre-wrap`; no HTML is interpreted. No outline sidebar.
- Completion: one button; name "Mark as complete" when not complete, "Mark as incomplete" when complete; while saving the name is "Saving…" and it is disabled. After success an element `role="status"` shows "Marked as complete." or "Marked as incomplete." and persists until the next action or navigation. Failure messages in `role="alert"` (exact text in the spec); the button is enabled again and has its previous name.
- Link "Try the practice set" to `/student/practice`; button "Ask your companion" opens the study companion.
- Not found: heading level 3 "Lesson not found" and link "Return to materials" to `/student/materials`.
- Sending: the button handler ignores clicks while a save is in flight (a synchronous ref), so a double click sends one request.
- The request body is `{"completed": !current}` where `current` is the last server-confirmed state.

Overview stat: the existing `Stat` with label "Lessons completed"; value "N / M" and detail "N of M lessons"; loading value "…" and detail "Loading…"; failure value "–" and detail "Unavailable. Open Study materials to try again."; demo 401 detail "Sign in to see your progress".

Also fixed per screen (labelled entries):
- Requests per load and per retry: the Materials page sends one courses request on load and then one lessons request for the selected course; the lesson page sends one lesson request; "Try again" repeats only the failed request; the Overview stat sends one courses request. Development builds run effects twice, so identical in-flight GET requests are shared (never across a session change or a completion save).
- Wrong role: a teacher or admin who opens `/student/...` is redirected by the SHR-01 role guard to their own area before any request is sent; a 403 alert appears only if the role changes after load; demo mode shows the sign-in notice.
- Link history: push or replace: lesson cards, the "All study materials" back link and the course select all push a new history entry (nothing replaces); topic buttons and search are client side and do not change the URL.
- No generic failure message: every failure uses the exact message in the spec's tables; there is no catch-all text.

Timeouts: every request uses `REQUEST_TIMEOUT_MS` (10 s) from `client.ts`. No custom timeout, no automatic retry.

Responsive and theme: no fixed-width elements; lesson cards in the existing `material-grid`; the same CSS classes as today (`lesson-card`, `lesson-reader`, `back-link`, `toolbar`, `filter-buttons`).

## Decisions
- `published_lesson` is a snapshot table separate from `study_note_draft`, so later draft edits cannot change what students read and drafts have no student path (TEA-03 rule). Agreed (spec Decision 1).
- Completion is one row per (user, lesson) with a boolean, not a log of events: simple, idempotent, directly countable by STU-04. History of toggles is not kept (`updated_at` only).
- The request carries the desired state, not "toggle", so retries and double clicks cannot flip the state back.
- `course_id` is denormalised into `lesson_completion` with a composite FK so per-course counts need no join to the lesson and a mismatch is impossible.
- Withdrawn lessons are hidden but their completion rows are kept (no data loss if a lesson is reinstated).
- Paths use `/api/study/...` to avoid clashing with `/api/courses/{id}` (SHR-01) and `/api/practice-sets` (STU-02).
- Not optimistic in the UI: the button changes after the server confirms, so the screen never claims a state the database does not hold.
- Plain text rendering only; no Markdown dependency added. No new Python or npm dependency, no new environment variable.
