# Plan: STU-02 Practice attempt API (server-side core)

## Contract (fixed; developer and test-designer work from this alone)

Identity: header `X-Student-Id` (any non-empty string). Missing or empty gives 401 on every attempt endpoint and on attempt creation. Reading a set needs no header.

Error body, always: `{"detail": {"code": "<code>", "message": "<text>"}}`, with extra fields where stated. Messages must not contain the answer key or explanations. Malformed request bodies may use FastAPI's default 422 body.

| Method and path | Success | Errors |
|---|---|---|
| `GET /api/practice-sets/{set_id}` | 200 `{"id", "title", "questions": [{"id", "text", "code": str or null, "choices": [{"id", "text"}]}]}` | 404 `set_not_found` |
| `POST /api/practice-sets/{set_id}/attempts` | 201 `{"attempt_id", "set_id", "status": "in_progress", "answers": {}}` | 401 `missing_student`; 404 `set_not_found` |
| `GET /api/attempts/{attempt_id}` | 200 `{"attempt_id", "set_id", "status": "in_progress" or "submitted", "answers": {question_id: choice_id}}` | 401 `missing_student`; 404 `attempt_not_found` (unknown or not owned) |
| `PUT /api/attempts/{attempt_id}/answers` body `{"answers": {question_id: choice_id}}` (merged into saved answers) | 200 `{"attempt_id", "status": "in_progress", "answers": {all saved answers}}` | 401; 404 `attempt_not_found`; 409 `already_submitted`; 422 `unknown_question` or `invalid_choice` (nothing is saved from a rejected request) |
| `POST /api/attempts/{attempt_id}/submit` (body ignored) | 200 `{"attempt_id", "status": "submitted", "score": {"correct": int, "total": int}}` | 401; 404 `attempt_not_found`; 409 `already_submitted`; 422 `incomplete` with extra field `"missing": [question ids in set order]` |
| `GET /api/attempts/{attempt_id}/results` | 200 `{"attempt_id", "set_id", "key_version": "v1", "score": {"correct", "total"}, "answers": {...}, "questions": [{"id", "selected", "correct_choice", "correct": bool, "explanation"}]}` in set order | 401; 404 `attempt_not_found`; 403 `not_submitted` |

Check order on attempt endpoints: header (401), then ownership and existence (404), then state (409, 403), then input validation (422).

Attempt ids are opaque strings generated by the server (not guessable sequential integers).

## Structure (single responsibility; the developer chooses file names)
Keep these concerns in separate modules under `src/backend/`: the fixture data (questions and key); response and request schemas; the attempt store (in-memory, behind an interface so a database can replace it); the scoring and validation logic; and the HTTP routes. `main.py` only wires the router in. Reuse, do not duplicate, the header check.

## Tests
Backend pytest in `src/backend/tests/`, using the same ASGI client style as `test_health.py`. Each acceptance criterion maps to at least one test named `test_stu02_...`. Include adversarial cases for AC8 and AC9. Tests must be independent of each other (use unique student ids).

## Decisions
- Header identity is a placeholder for SHR-01.
- Another student's attempt returns 404, not 403, so existence is not revealed.
- Fixture data is code, not a database, for this slice.
