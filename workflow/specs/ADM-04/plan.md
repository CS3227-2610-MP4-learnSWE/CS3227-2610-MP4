# Plan: ADM-04 Feedback follow-up

Status: Approved by user in chat, 2026-11-07.

## Data model
Add durable `admin_message_previews`: UUID id, owner_admin_id, kind (`feedback_response` or `announcement`), optional feedback_response_id, audience_role (`student` or `teacher`), normalized subject/body, sorted frozen recipient IDs and display snapshots, created_at, expires_at, optional sent_message_id. Store recipient membership relationally if needed for bounded transactional checks. Add `admin_messages`: UUID id, preview_id unique, sender_admin_id, kind, optional source_feedback_response_id, subject/body, sent_at. Add `admin_message_deliveries`: UUID id, message_id foreign key, recipient_id opaque account foreign key, read_at nullable UTC; unique `(message_id, recipient_id)`, initially unread. Survey persistence is reused only as a design pattern; the existing feedback-recipient table remains unchanged. Private source-response linkage remains admin-only and is omitted from inbox DTOs. Use additive migration, indexed ownership/preview keys, UTC timestamps, foreign-key/history semantics compatible with account archival. Existing survey messages/read state remain unchanged.

Recipient snapshot has id, display_name, role. These fields are admin-only; recipient inbox sees message kind, subject, body, sent_at and its own read status only. No response answers, recipient list/count or sender email enters inbox payloads. Preview and message retention follow spec. All-or-nothing fan-out and persisted idempotency must survive worker restart; process-local locks alone are insufficient.

## API endpoints
All endpoints below require a current active admin. Prefix `/api/admin/messaging`. JSON uses snake_case. Account IDs are opaque case-sensitive strings, other ID fields are UUID strings, timestamps RFC3339 UTC, enums exact. Reject extra fields. Errors use the existing shared application envelope. Exact shape: `{"detail":{"code":"CODE","message":"exact copy"}}`; optional `retry_after_seconds` is permitted inside detail for 429.

1. `GET /feedback-responses/{response_id}/recipient` -> 200 `{response_id, recipient:{id,display_name,role}}`. Derive recipient from submitted response, not form targets or client input; missing/unsubmitted/unavailable respondent -> 404 `RECIPIENT_UNAVAILABLE`.
2. `GET /recipients?role=student&search=&page=1&page_size=50` -> 200 `{items:[recipient],page,page_size,total}`. role required student/teacher; search at most 100 characters; page at least 1; page_size fixed 50, last page may be shorter. Only active nonarchived accounts; deterministic case-insensitive display_name then exact account-ID lexicographic sort. Empty page allowed. `total` counts filtered results, not selected audience. No cross-role IDs.
3. `POST /previews` -> 201 Preview. Discriminated request:
   - response `{kind:"feedback_response",response_id,subject,body}`; no audience or recipient override accepted.
   - announcement `{kind:"announcement",audience_role:"student"|"teacher",audience_mode:"all_active"|"selected",recipient_ids?:[AccountID],subject,body}`. `selected` requires recipient_ids; `all_active` forbids recipient_ids. Resolve and validate all eligible recipients transactionally; zero/>500 -> 422 `INVALID_RECIPIENTS`; mismatched/missing/inactive selected IDs -> 409 `AUDIENCE_CHANGED`. Freeze full resolved audience.
   Preview `{id,kind,response_id:null|UUID,audience_role,audience_mode:null|"all_active"|"selected",subject,body,recipients:[recipient],recipient_count,created_at,expires_at}`. Account IDs sorted lexicographically ascending; count equals array length. No answers or server-generated message text.
4. `POST /previews/{preview_id}/send`, empty JSON `{}` only -> 200 Receipt `{message_id,preview_id,kind,recipient_count,sent_at}` both first send and replay. Lock preview, recheck active admin and ownership, return sent receipt before expiry/staleness checks for an already sent preview. Otherwise enforce expiry and send quota, revalidate exact eligible audience, then atomically persist message/deliveries and link sent_message_id. For all_active compare current full eligible set to frozen IDs; additions/removals or display-name changes require review. Selected/response recipient display-name changes also require a fresh review. For selected/response verify frozen users still eligible and source response still points to same respondent. Foreign admin preview indistinguishable from missing: 404 `PREVIEW_UNAVAILABLE`. Expired -> 409 `PREVIEW_EXPIRED`; changed audience -> 409 `AUDIENCE_CHANGED`. Failed transaction leaves no message/delivery and allows safe retry.

Shared error codes: 401 `unauthenticated` with server message `Sign in to continue.`; 403 `forbidden` with server message `You do not have access to this.`; 403 `csrf_failed` with shared server message `The request could not be verified.` (UI `Your security session has expired. Refresh the page and try again.`); 404 `RECIPIENT_UNAVAILABLE`/`PREVIEW_UNAVAILABLE`; 409 `AUDIENCE_CHANGED`/`PREVIEW_EXPIRED`; 422 `INVALID_SUBJECT`/`INVALID_BODY`/`INVALID_RECIPIENTS`/`INVALID_REQUEST`; 429 `MESSAGING_RATE_LIMITED`; 413 `REQUEST_TOO_LARGE`; 500 `MESSAGING_ERROR`; 503 `MESSAGING_UNAVAILABLE`. Client maps 413/500 and CSRF to exact spec copy. Raw framework/server exception text is never shown. Copy is exactly spec.md. Framework malformed bodies/UUID/query values must map to 422 INVALID_REQUEST, not stack traces. Cache-Control no-store on private responses. Same-origin/cookie CSRF protection follows shared authentication mechanism. Never include private payloads in error text.

5. `GET /previews/{preview_id}` -> 200 `{preview:Preview,receipt:null|Receipt}`. Active owner admin only; foreign/missing -> 404 PREVIEW_UNAVAILABLE; unsent expired -> 409 PREVIEW_EXPIRED. A sent preview remains recoverable after expiry. GET never sends and returns immutable preview-time display snapshots. Refresh after uncertain send uses this endpoint, then retries only the same send ID if receipt is null.

Recipient endpoints require active student/teacher and existing CSRF policy for writes:
- `GET /api/messaging/inbox?limit=20&offset=0` -> `{items:[{id,kind,subject,body,sent_at,read_at}],next_offset:null|integer,unread_count:integer}`. Limit fixed 20, offset nonnegative, newest sent_at then delivery UUID descending; body included in list, maximum 20*5000 characters. `id` is delivery UUID. Only owned deliveries; unread_count covers this Messages section only.
- `POST /api/messaging/inbox/{delivery_id}/read`, `{}` -> `{id,read_at}`; atomic idempotent first read timestamp. Foreign/missing -> 404 `MESSAGE_UNAVAILABLE`, copy `This message is unavailable.`. Anonymous shared 401; wrong role shared 403; invalid input 422; dependency failure 503; all no-store. No recipient list/count, raw response data or feedback URLs in any recipient DTO.

Preserve existing survey API `GET /api/feedback/inbox?limit=20&offset=0` and its exact `{items:[{id,form_id,title,created_at,read_at,state,submitted,response_status}],next_offset,unread_count}` response and survey/read workflows. At `/student/inbox` and `/teacher/inbox`, add separate h2 `Messages` below surveys, with one new messages GET per mount in addition to unchanged survey calls. Section status `Loading messages…`, empty `No messages yet.`, button `Load more messages` (one next-page GET), button `Retry messages` (one failed-page GET). Each message article accessible name is its subject; show `Announcement` or `Feedback response`, subject, body, timestamp, `Unread`/`Read` text and button `Mark as read` only while unread. A click issues one read POST, disables button until complete, updates local unread_count once; failure preserves unread and shows exact mapped alert. Section status `{count} unread messages` is independent of the existing survey unread counter. No combined badge or polling introduced. Survey failure cannot hide Messages, nor vice versa. Inbox network/timeout/503/429 use spec copy; 401 clears and redirects, 403 replaces to own area. Read failure retry is `Mark as read` again; messages list failure retry is `Retry messages`. No new recipient-detail route is needed because the full message is in the section. Backend ownership is enforced independently of what UI exposes.

Transport: reject bodies over 128 KiB with 413 REQUEST_TOO_LARGE before JSON parsing; reject duplicate/unknown query keys and any unsupported query on non-list endpoints with 422 INVALID_REQUEST. Page is a positive integer, page_size must equal 50; inbox limit must equal 20. Missing optional list parameters use the displayed defaults. Recipient reads (including preview recovery) allow 20/minute/admin; recipient inbox list/read operations allow 60/minute/account, shared across both. Return 429 MESSAGING_RATE_LIMITED when exceeded, with positive retry_after_seconds. Existing shared limiter is process-local; durable send uniqueness remains database-enforced.

Public independent tests target the fully specified HTTP contracts above; internal function signatures are developer-owned and must not be guessed by the test-designer. Existing ADM-02 detail GET `/api/admin/feedback/forms/{form_id}/responses/{response_id}` exposes admin-only respondent `{id,display_name}`; source recipient IDs must derive from that persisted submitted record, not client-supplied metadata.

## UI contract
URLs: `/admin/feedback/{form_id}/responses/{response_id}/reply` and `/admin/announcements/new`. Existing parent response route is `/admin/feedback/{form_id}/responses/{response_id}`. Entry `Respond to feedback` is a link on submitted response detail only. `Announcements` is an admin navigation link. Composer h1 `Respond to feedback` or `New announcement`. `Subject` is a single-line textbox; `Message` a multiline textbox. All review/failure/success copy, field limits and timing are exactly spec.md. Recipients use semantic list accessible name `Recipients`; error messages role alert and progress/success role status. `Confirm send` is disabled during send; editing clears preview. Focus review h1 on review; focus first invalid field on validation; success h1 on receipt. Buttons remain usable at 320px width; long subjects, names and message lines wrap; respect reduced motion.

- Requests per load and per retry: review query one preview GET instead of composer GET; response one recipient GET; announcement one recipients GET; each search (300 ms debounce), page or role change one list GET; each Review message one preview POST; each Confirm send one send POST. Retry only failed operation once per click. No send occurs on mount, history or refresh. Review success replaces URL query with `review={preview_id}`; this durable ID survives refresh/back and allows GET recovery after uncertain send. Edit clears query by replace. After preview POST, replace query and render returned preview without an extra GET; only a later mount/history/refresh performs preview recovery GET. Edit reconstructs text, mode and selected IDs from the preview, removes query by replace and performs exactly one recipient list GET (or one recipient GET for response). Missing/expired recovered review shows its exact alert and button `Start a new message` (clears query by replace, then loads empty composer once); no unavailable server text can be reconstructed after refresh. An in-memory stale/expired send returns to populated composer retaining fields, mode and IDs and loads eligibility once. Preview display names are frozen at preview creation; sending revalidates eligible IDs, roles and display names; any changed visible recipient identity requires a fresh review. Cancel stale list requests, retaining selection by IDs across pages and searches. Default Students/All active users; selection changes require fresh review. No live unread polling introduced; existing inbox refresh/read patterns apply.
- Wrong role: replace to own role home with no messaging calls; anonymous replace to login; expired session clears all private state. Server authorization is independent of UI routing.
- Link history: push or replace: entry and Back to feedback push; review/edit use query replace; send/receipt retain query; New announcement clears query by replace; auth and role redirects replace. Refresh and Back/Forward follow spec: empty composer without review query, durable preview/receipt recovery with review query.
- No generic failure message: exact spec code-to-copy mapping; only genuine network errors use connection copy. Fifteen-second timeout and explicit Retry; send retry retains preview ID. 409/preview 404 invalidate review and return to retained composer; 429/503/network/timeout retain preview and allow safe retry. 401/forbidden 403 clear everything; csrf_failed retains fields and shows refresh instruction. Role changes clear selected IDs; failed actions never silently change message or audience.
