## Goal
From the user stories: a teacher views lesson completion rates (US-TEA-05-01) and practice results with commonly missed questions (US-TEA-05-02) for the courses the teacher manages, for a stated reporting period, so they can see where students stop and what to explain again. The report replaces the sample figures on the teacher Overview.

## Behaviour
A signed-in teacher opens `/teacher/overview`. Below the unchanged page heading and hero, a section "Learning overview" shows the report for every course the teacher currently manages (membership in `course_membership`), ordered by lower(title) then id. A select "Reporting period" chooses the period; changing it reloads the report. Each course has its own panel with: a summary (students enrolled, published lessons, lesson completion rate), a "Lesson completion" table (one row per published, non-withdrawn lesson), a "Practice results" table (one row per published practice set) and a "Commonly missed questions" list (top 5). A note "How these figures are calculated" explains every number.

Aggregates only: the report never contains student names, ids, emails, individual scores or answers, and never the correct answer, choices or explanation of a question. Question text and lesson/set titles are the teacher's own published content.

### Reporting period
Boundaries are UTC calendar days, half-open `[start, end)`, `end` = 00:00 UTC on the day after today.
- `7d` Last 7 days: today and the previous 6 UTC days (`start` = 00:00 UTC six days ago).
- `30d` Last 30 days: today and the previous 29 UTC days.
- `all` All time: no start bound.
The response names the period and the server time `as_of`. The screen shows e.g. `Period: Last 30 days, 2026-10-11 to 2026-11-09 (UTC)` (inclusive dates) or `Period: All time, up to 2026-11-09 (UTC)`.

### Calculations (the documented rules shown in the note)
- Students: current members of the course whose account role is `student`. Disabled students are counted (they remain enrolled); archived accounts have no membership. A student removed from the course drops out of every figure.
- Lesson completed in the period: the student's lesson record is currently "completed" and its completion time is inside the period. A completion that was later undone does not count. Only published, non-withdrawn lessons count.
- Lesson `Completion rate` = students who completed it / students enrolled, rounded down to a whole percent; not available when no students are enrolled.
- Course `Lesson completion rate` = completions in the period / (students enrolled x published lessons), rounded down; not available when either is 0.
- Practice: only submitted attempts by enrolled students on the course's published practice sets, submitted inside the period. `Submitted attempts` counts all of them; `Students attempted` counts distinct students. `Average score` uses each student's latest submitted attempt in the period: total correct answers / total questions answered across those attempts, rounded down; not available with no attempts. (Practice sets outside the published course content, such as built-in sample sets, are not included.)
- Commonly missed question: among those latest attempts, `missed` = attempts where the question was answered and not answered correctly; `answered` = attempts where it was answered; miss rate = missed / answered, rounded down. Only questions missed at least once are listed. The list shows the 5 highest, ordered by exact miss rate, then more misses, then set title (case-insensitive), then question position.
- Percentages round down (as in the student progress page).
- Limits: the figures show current enrolment and current completion records only; history of un-done completions or removed students is not reconstructed.

- Requests per load and per retry: one `GET /api/teacher/overview?period=30d` per history-entry activation of `/teacher/overview` after the session resolves (the page is remounted for every history entry, as for ADM-06; development StrictMode must not send two); one GET per period change; one GET per `Try again`; zero for anonymous or wrong-role visitors. No polling, no automatic retry. Shell requests (session check, inbox badge) are separate and unchanged.
- Wrong role: a signed-in student or admin opening `/teacher/overview` is redirected with replace to their own area by `RequireRole` and no overview request is sent. A direct API call returns 403 `forbidden`; a mid-session 403 shows the 403 alert without `Try again`.
- Link history: push or replace: the sidebar "Overview" link and the hero links push. Period change and `Try again` do not change the URL (no query parameter; the period lives in memory). Wrong-role and expired-session redirects replace.
- Refresh: the session is restored, then one GET with `Last 30 days`; the previous report is never restored from storage or the HTTP cache.
- Back and Forward: each history entry resets the period to `Last 30 days`, clears the old report immediately and sends one fresh GET.
- Expired session or logout: existing shared shell, "Confirm logout" flow and session-generation protection. Successful logout or a 401 clears the report and period choice; a failed logout keeps the session and the report. Back after logout cannot show a cached report. A newly signed-in account never receives a former account's pending response.
- Backend down: the network alert (or the 503 alert for a known database outage) with `Try again`; hero and period select stay.
- Longest wait before an error: 15 seconds per overview request, then the timeout alert; late responses of aborted or superseded requests cannot overwrite a newer result.
- No generic failure message: every failure uses its own message from the table; "Could not reach the server..." only for a real network failure.

## Security and AI safeguards
Server-side only: the endpoint uses `teacher_session` (role teacher, active account) and returns data only for courses where the session user is currently a member. The ids of students are used inside the server to count and are never returned. Only counts, percentages and teacher-owned content (titles, topic names, question text) are returned; answer keys, choices, explanations, draft and withdrawn content, answers and individual scores are never selected into the response. The period is the only client input and is validated against an allow-list. All rendering is plain text (React text nodes). No AI call is made: no report data enters a prompt (SHR-02 is satisfied by absence; a test asserts the endpoint calls no LLM client). Output size is bounded per course by the data a teacher publishes, with the missed-question list capped at 5 (see Open question 4). Requests are limited to 30 per 60 seconds per teacher.

- Concurrent requests (same time): the endpoint is read-only. Simultaneous identical requests return equal bodies when no data changes. Within one response the numbers are consistent: one student roster per course is read first and every other count is limited to that roster, so `completed_students` can never exceed `student_count` and no rate exceeds 100 even if a student is enrolled, removed or completes a lesson while the request runs. Concurrent enrolment, completion and submission writes are neither blocked nor changed.
- Normalisation: `period` is trimmed of surrounding ASCII whitespace, then compared case-sensitively to `7d`, `30d`, `all`; repeated, unknown or missing keys are 422. Ids come from the session. Course and set ids are compared as canonical lowercase UUID strings (attempt `set_id` is text; published set ids are `str(uuid)`), so non-UUID built-in set ids never match. Time is compared as aware UTC instants.

## Open questions
Each has a recommended answer used in this draft; the user confirms with approval.
1. Disabled students: counted as enrolled (recommended: simplest, matches membership; they stay on the roster). Alternative: count only `enabled` students so the rates describe active learners.
2. Small cohorts: with 1 or 2 students an aggregate reveals an individual's progress to the teacher who manages that course. Recommended: no minimum cohort size (the teacher is authorised for the course and cannot see names in the report); the UserGuide states that figures are course totals. Alternative: hide rates below N students.
3. Frontend transport: the starting contract said `requestTeacher`, but `requestTeacher` cannot tell a timeout from a network failure (it never sets `distinguishTimeout`), which would break "no generic failure message". Recommended: the service uses the shared `request` from `services/client.ts` with `{ timeoutMs: 15000, distinguishTimeout: true, cache: "no-store" }`, as `aiUsage.ts` does, and shares the 401 and session-generation handling. Alternative: extend `requestTeacher` (shared, touches other teacher screens).
4. Output size: lesson and set lists are not capped (teacher content is small); only the missed list is capped at 5. Recommended: accept for the MVP and note the limit. Alternative: cap 100 sets and 200 lessons per course with a "truncated" flag.
5. Averages: `Average score` is pooled (total correct / total answered over each student's latest attempt in the period) so it matches the miss-rate arithmetic and reuses `progress_rules.accuracy_percent`; STU-04 uses a mean of per-set percentages for a different view. With the fixed 3 questions per set the two are equal. Recommended: pooled.
6. Decision "repeat-attempt scoring ... and the rule for identifying weak topics" (UserStories): this feature uses each student's LATEST submitted attempt in the period (consistent with STU-04's latest score) and no weak-topic threshold (no minimum number of answers; `answered` is shown so small samples are visible). Alternative: best attempt, or all attempts. Recommended: latest.
7. Completion-in-period semantics: for `Last 7 days` the rate is "completions made in the period / all possible student-lesson pairs", not "students who have ever completed". `All time` gives the cumulative rate. Recommended: keep and state it in the note (done); alternative is always cumulative with the period used only for practice.
8. Period alignment: UTC calendar days including today (not a rolling 168 hours) so the shown dates are exact and tests can use fixed boundaries. Recommended: keep.
9. Resolved 2026-11-09 by the user: fix it here (AC17). The heading description becomes "Welcome back, {display_name}." using the signed-in teacher's `display_name` from the auth context; the anonymous demo shows "Welcome back." No other heading or hero text changes.
10. Shared specs: the exact list of existing browser specs that sign in a teacher and reach `/teacher/overview` is in `plan.md`; the test-designer confirms it by searching and reports any existing assertion that the new background request breaks instead of editing it.
11. Other listed decisions (initial subject and level, upload formats, feedback identity and retention, SoC quotas, ADM-05 enrolment) do not change this feature; ADM-05's manual enrolment and fixed roles are inherited (a student can only appear through an admin enrolment).
